# 3. LangChain으로 모델·메시지·도구 연결하기

[전체 진행표](README.md) · 이전: [공시 도구](02-filing-tools-and-transports.md) · 다음: [LangGraph](04-langgraph-state-and-resume.md)

목표는 모델이 요청한 도구 호출과 실제 실행 결과를 구분하고, 사용량을 추적하는 것이다. 자동 에이전트 전체를 먼저 가져오기보다 한 번의 왕복을 직접 이해한다.

## 준비

계획의 목표는 Python 3.14, MCP 2.1.1, LangChain 1.4.2, LangGraph 1.2.12다. 현재 의존성 파일에는 LangChain·LangGraph가 없다. [pyproject.toml](../pyproject.toml)과 [uv.lock](../uv.lock)의 기존 버전을 보존하면서 필요한 의존성만 추가하고 잠금 결과를 확인한다.

MCP 연결은 [`langchain.mcp.MCPAdapter`](https://docs.langchain.com/oss/python/langchain/mcp)를 사용한다. `langchain[mcp]` extra가 필요하며 내부 클라이언트 의존성이 추가된다. 이 어댑터와 서버용 공식 SDK의 `MCPServer`는 역할이 다르다. `langchain-mcp-adapters`와 병행하지 않는다.

선택할 모델 통합 패키지와 SQLite checkpointer도 목표 버전에 맞춰 확인한다. 단순 의존성 해결, import 성공, 실제 MCP 연결 성공을 각각 검증한다. 이 가이드는 아직 설치되지 않은 API의 완성 코드를 제공하지 않는다.

## 읽을 코드

- [provider.py](../app/agent/provider.py): 현재 provider 요청·응답과 사용량
- [types.py](../app/agent/types.py): 도구 호출·관찰·최종 답변·예산
- [loop.py](../app/agent/loop.py): 호출 ID와 결과를 연결하는 방식
- [ai_allowance.py](../app/release/ai_allowance.py): 실제 과금 호출 전 허용량 예약

## 직접 할 일

1. 사용자 메시지 하나, 도구 호출을 포함하는 모델 응답 하나, 해당 호출에 대한 도구 결과 하나를 작성한다. 서로 연결하는 ID를 표시한다.
2. 모델 없이 `MCPAdapter`로 실제 서버의 도구를 발견하고 정상·실패 호출을 해본다. adapter가 도구 오류를 어떻게 표현하는지 기록한다.
3. 결정적인 모델 대역으로 “검색 요청 → MCP 실행 → 결과 메시지 → 최종 답변” 한 바퀴를 구현한다.
4. 모델이 잘못된 도구 이름·인자·호출 ID를 내면 어느 경계에서 거부할지 정한다. 도구 실행 전 입력과 권한을 검사한다.
5. 최종 답변의 구조화 출력과 의미 검증을 나눈다. Pydantic 검증에 성공한 답변도 근거 없는 인용이면 끝낼 수 없어야 한다.
6. 실제 모델 검증은 예상 비용과 호출 수를 확인한 뒤 질문 하나로 한다. model ID, 사용량, 비용 산정 기준, 종료 사유를 기록한다.

## 결과를 예측하기

| 상황 | 확인할 질문 |
|---|---|
| 모델이 도구 이름과 인자만 반환 | 검색은 이미 실행됐는가? |
| 도구 실패를 정상 메시지로 전달 | 모델과 그래프가 실패를 구분할 수 있는가? |
| 호출 하나에 결과 ID가 다름 | 모델 입력 메시지 계약을 위반하는가? |
| 토큰 사용량이 응답에 없음 | 0으로 계산하면 예산이 안전한가? |
| SDK의 내부 retry 활성화 | 실제 호출·비용 횟수를 어떻게 파악하는가? |

사용량을 알 수 없는 경우 무료 성공으로 처리하지 않는다. 모델 비용과 MCP 검색 안의 임베딩·번역 비용을 합산할 책임을 정한다. HTTP를 건너면 기존 프로세스의 비용 문맥도 자동 전달되지 않는다.

## 검증과 통과 기준

새 모델 연결 코드에는 구현 경로에 대응하는 테스트를 둔다. 기존 `tests/agent/test_provider.py`와 `test_loop.py`를 참고하되 구현 내부를 그대로 복제한 기대값은 쓰지 않는다.

- [ ] 도구 호출 제안과 실제 실행을 각각 추적한다.
- [ ] 호출 ID, 입력, 결과 또는 오류가 올바르게 연결된다.
- [ ] 어댑터가 실제 MCP 서버를 통과하는 연결 검증이 있다.
- [ ] 구조화 출력 성공과 근거 검증 성공을 구분한다.
- [ ] 유료 실행을 했다면 실제 사용량과 누적 비용을 확인했다.

대역 모델 통과만으로 실제 모델 통합을 완료 처리하지 않는다. 반대로 유료 호출을 매 코드 수정마다 반복하지 않고, 유효한 결과를 재사용한다.
