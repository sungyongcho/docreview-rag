# Meridian Code Academy — API General Terms of Use

These Terms govern student access to the MCA intranet API. Sample content for a
document-review demo.

## 1. Purpose

The API provides limited, read-only access to intranet data so students can build
educational projects that benefit the MCA community. Access is restricted to enrolled
students and alumni; candidates may not use the API.

## 2. License

### 2.1 License from MCA
MCA grants a limited, non-exclusive, revocable, non-transferable, non-sublicensable license
to access and use the API. MCA retains all intellectual-property rights in the API.

### 2.2 License from the user
The user grants MCA a non-exclusive, royalty-free, worldwide license to host and use content
the user submits through the API for educational purposes connected to operating or
improving MCA tools.

## 3. Access and Authentication

### 3.1 Read-only access
The API is read-only. Storing API data locally is prohibited without the prior consent of
the end-user the data concerns.

### 3.2 Tokens and limits
Access requires a token obtained after intranet authentication. A token is valid for
90 minutes and must be regenerated after it expires. The API secret is rotated every
14 days. A rate limit of 1,200 requests per hour per token applies.

### 3.3 Confidentiality
Tokens, API secrets, and passwords are strictly confidential and must not be shared with any
third party, inside or outside MCA.

## 4. Prohibited Practices

Users must not: sell or license API data; place API data on a search engine or otherwise
make it available outside the MCA network; give a non-authorized third party access to the
API; reverse-engineer the API; or use API data to send advertising without prior
authorization.

## 5. Security Measures for Applications

Any application exposing API data must ensure confidentiality, integrity, and availability;
enforce a password policy; perform regular backups; monitor access authorizations; and
encrypt data in transit and at rest.

## 6. Breach Notification

Users must report any risk to data confidentiality or API security to
security@meridiancode.example as soon as possible. On suspected compromise of access keys,
the user must revoke them immediately and request new keys.

## 7. Data Retention by Users

Unless retention is legally required, users must delete API data when it is no longer needed,
when the application stops operating, when MCA requests deletion, or when the end-user
requests deletion.
