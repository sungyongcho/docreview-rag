# M1.2 명세

> 코드: `app/ingestion/tables.py` · 검증: [05-verify.md](05-verify.md) 앞 단계: [`m1-1-parser/`](../m1-1-parser/00-README.md) (10-K → Item 섹션 파서)

## 한 문장

**SEC 표는 데이터 표가 아니라 레이아웃 표다.** 그래서 이 모듈은 직렬화가 아니라 **레이아웃 걷어내기**가 본체다.

---

## 1. 입력 사실과 설계 결정

전체 실측은 [01-findings.md](01-findings.md)가 소유한다. 핵심은 SEC 표가 논리적 데이터 격자가 아니라 인쇄 레이아웃이라는 점이다. 따라서 이 모듈의 계약은 단순 직렬화가 아니라 **레이아웃 축소 후 의미 보존 직렬화**다.

### 이게 무슨 뜻인가

NVDA-FY2024 손익계산서(비율)의 실제 구조다. 논리적으로 **3열**인 표가:

```
r0   n=12  [''] [''] [''] [''] [''] [''] [''] [''] [''] [''] [''] ['']
r1   n=2   [''x3] ['Year Ended'x9]
r2   n=4   [''x3] ['Jan 28, 2024'x3] [''x3] ['Jan 29, 2023'x3]
r3   n=6   ['Revenue'x3] ['100.0'x2] ['%'] [''x3] ['100.0'x2] ['%']
```

물리적으로 **12열**로 들어온다 — 라벨(colspan 3) · 값(colspan 2) · 단위 · 스페이서(colspan 3). `r0`은 셀 12개가 전부 빈 순수 스페이서 행이다.

**이 HTML을 그대로 마크다운으로 옮기면 중앙값 기준 63.6%가 빈 넓은 격자가 된다.** 원문 텍스트보다 검색에 나쁘다. 그래서 붕괴가 먼저다.

---

## 2. 파이프라인

```
L2 to_grid              colspan/rowspan -> dense matrix
L3 drop_empty           remove empty axes         (12 -> 5 columns, p50)
L4 merge_unit_columns   fold '$'/'%' columns into values
L5 split_header         infer header rows         (no <th> exists)
L6 to_markdown          serialize markdown
L7 table_to_markdown    compose the entry point
```

### L2 — 그리드 전개

**핵심 결정: span된 셀의 텍스트를 복제하지 않는다.** 좌상단에만 남기고 나머지는 빈 문자열이다. 복제하면 이 코퍼스에선 **숫자가 통째로 두 번 세어진다** — 값 셀이 `colspan`을 쓰기 때문이다.

`(r, col) in filled` 검사가 rowspan이 이미 차지한 자리를 건너뛴다. `filled`가 점유와 텍스트를 겸하므로 별도 점유 맵이 필요 없다.

### L3·L4 — 붕괴 ★

전체 셀은 L2 **221,730** → L3 **69,241** → L4 **66,575 (30.0%)** 순서로 줄었다. 빈 축 제거와 단위 열 병합을 합치면 레이아웃이 그리드의 **70%**였다.

| | 전 | 후 |
|---|---|---|
| 열 p50 | 12 | **5** |
| 열 p90 | 30 | **11** (L4 뒤 10) |
| 열 max | 66 | **25** |

내용이 아예 없는 표 **26개**도 여기서 걸러진다(전부 순수 스페이서). AMD·INTC에만 있고 MU·NVDA엔 0인 것이 회사별 조판 차이를 그대로 보여준다.

### L4 — 단위 열

`$`는 숫자 **앞**, `%`는 숫자 **뒤**로 접는다. 읽는 순서를 따른다. 안 하면 붕괴 후에도 기호만 든 열이 **279개** 남는다.

### L5 — 헤더 추론

`<th>`가 0개이므로 모양으로만 판별한다.

> **헤더 행은 라벨 열이 비어 있고 나머지 열에 글자가 있는 선두 행들이다.**

데이터 행은 항상 항목 이름으로 시작하므로 이 규칙으로 구분할 수 있다. 다단 헤더("Year Ended" 위에 "Jan 28, 2024")는 열별로 합쳐서 **숫자가 어느 기간 것인지**를 청크 텍스트에 남긴다.

매칭이 없으면 `([], grid)`를 반환한다 — 빈 헤더를 지어내지 않고 **판단은 호출부가 한다.**

## 4. 결정 두 가지 (근거와 함께)

### `Block.text`를 채우지 않는다

계획 초안의 계약은 `Block(kind="table", html=...)` → `Block(text=<markdown>)`였다. **이를 변경했다.**

`parser.py`는 표 블록을 `Block("table", "", html=str(el))`로 만든다 — `text`가 비어 있다. 그리고 커버리지 지표가 `body = sum(len(b.text) ...)`로 계산된다. 여기에 마크다운을 채우면 **COVERAGE 골든 20개가 전부 어긋난다.**

그래서 이 모듈은 **HTML에 대한 순수 함수**로 둔다. `Block`을 건드리지 않고, 청커(M1.3)가 필요할 때 `table_to_markdown(block.html)`을 부른다.

부수 효과가 아니라 이득이다:
- 표 렌더링이 커버리지 지표를 흔들 수 없다
- 파서가 마크다운을 모른다 — **아래층이 위층을 모른다**는 원칙 그대로

### 괄호 음수를 정규화하지 않는다

`(1,234)`를 `-1234`로 바꾸지 않는다. 3,073개를 그대로 보존한다.

- **인용이 원문과 같아야 한다.** 독자가 공시에서 보는 것과 청크가 달라지면 안 된다
- **적재 시점 정규화는 되돌릴 수 없다.** 질의 시점 정규화는 되돌릴 수 있다

판단이 틀렸다면 질의 쪽에서 고치면 되지만, 적재에서 틀리면 재적재해야 한다. **되돌릴 수 있는 쪽에 실수를 몰아둔다.**
