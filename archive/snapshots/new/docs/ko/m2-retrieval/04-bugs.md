# M2 버그

각 항목에는 증상, 근본 원인, 수정 사항, 회귀 방지책을 기록합니다. 측정된 최종 결과는 [조사 결과 F11](01-findings.md#f11--기록된-검증-근거)에 있습니다.

## B01 — 새 스키마에서 벡터 열을 생성할 수 없었음

상태: 수정됨.

증상: `create_all`은 PostgreSQL이 `vector(384)`를 인식하지 못해 실패했습니다.

근본 원인: pgvector는 서버 이미지에 설치되어 있지만 확장은 데이터베이스별로 활성화됩니다. SQLAlchemy가 확장을 활성화하기 전에 청크 테이블 생성을 시도했습니다.

수정: 동일한 부트스트랩 트랜잭션에서 `CREATE EXTENSION IF NOT EXISTS vector`를 `Base.metadata.create_all`보다 먼저 실행합니다. 시드 CLI의 명시적인 `--create-schema` 경로가 이 도우미를 통하도록 연결합니다.

회귀 테스트: `test_bootstrap_enables_vector_before_create_all` 및 실제 멱등성 테스트.

## B02 — 병렬 구성 요소 호출이 세션 상태를 손상할 수 있었음

상태: 계약으로 수정됨.

증상: 매력적으로 보이는 `asyncio.gather` 구현은 하나의 `AsyncSession`을 통해 벡터와 어휘 SQL을 동시에 실행합니다.

근본 원인: 비동기 구문을 사용한다고 해서 변경 가능한 SQLAlchemy 세션을 여러 태스크에서 동시에 안전하게 사용할 수 있는 것은 아닙니다.

수정: 하나의 세션을 캡처하는 두 어댑터를 주입하고, 벡터를 먼저 기다린 다음 어휘 검색을 기다립니다.

회귀 테스트: 서비스 테스트가 정확한 호출 순서와 세션 객체 식별자를 기록합니다.

## B03 — `R&D` 때문에 어휘 인수 목록이 비었음

상태: 실제 말뭉치 통합 후 수정됨.

증상: `"NVDA 2024 R&D"`에서 어휘 검색 결과가 나오지 않았고 Intel 청크가 NVDA보다 높은 순위를 차지했습니다.

근본 원인: PostgreSQL은 이 약어를 `'r' & 'd'`로 분석했지만, 관련 공시 텍스트는 `Research and Development`라는 전체 문구를 흔히 사용합니다. 결정론적 공급자도 분리된 글자를 해시했습니다.

수정: 프로덕션 서비스 경계에서 쿼리 임베딩과 어휘 검색을 수행하기 전에 `R&D`를 `research development`로 한 번 확장합니다.

회귀 테스트: 서비스 테스트는 두 구성 요소가 받은 정규화된 쿼리를 확인하며, 실제 인수 명령에서는 NVDA FY2024 청크가 1위를 차지합니다.

## B04 — 융합에서 서로 관련 없는 점수 척도를 비교했음

상태: 수정됨.

증상: 높은 `ts_rank_cd` 값이나 코사인 유사도가 관련성과 무관한 이유로 가중합을 지배할 수 있었습니다.

근본 원인: 두 값의 의미가 다르고 공유하는 보정 방식이 없습니다.

수정: RRF 처리 중 출처 점수를 무시하고 역순위 기여분만 더합니다. 구성 요소 순위는 점수 없이 청크 ID로 공개합니다.

회귀 테스트: RRF 테스트는 의도적으로 극단적인 출처 점수를 사용해 융합 결과에 해당 점수가 남지 않음을 검증하고, 서비스 페이로드는 순위만 있는 형태를 확인합니다.

## B05 — 근거를 확보하기 전에 근사 인덱스가 등장했음

상태: 방지됨.

증상: HNSW를 추가하면 시스템이 최적화된 것처럼 보이지만 M2에서 측정하지 않은 재현율 절충이 조용히 도입됩니다.

근본 원인: 흔한 프로덕션 최적화를 기본 정확성 요소로 취급했습니다.

수정: 정확한 pgvector 검색을 유지하고 근사 인덱스 결정은 M3의 지연 시간 및 검색 품질 측정까지 미룹니다.

회귀 테스트: 모델 및 SQL 테스트가 HNSW 인덱스가 없음을 확인합니다.

## B06 — 공급자와 데이터베이스의 차원이 달라질 수 있었음

상태: 수정됨.

증상: 공급자가 유효한 벡터를 반환했지만 차원이 `chunks.embedding`과 일치하지 않아 PostgreSQL이 거부했습니다.

근본 원인: 공급자 검증만으로는 활성 데이터베이스 모델의 차원을 알 수 없습니다.

수정: 임베딩이나 SQL을 수행하기 전에 공급자 차원을 `app.db.models.DIM`과 비교해 검증합니다.

회귀 테스트: 서비스는 32차원의 결정론적 공급자를 I/O 전에 거부합니다.

## B07 — 공급자를 전환해도 호환되지 않는 저장 벡터를 재사용했음

상태: 문서화된 M2 제한 사항.

증상: 결정론적 문서 벡터를 OpenAI 쿼리 벡터로 검색하면 둘 다 구성 요소가 384 개여도 의미 없는 코사인 거리가 생성됩니다.

근본 원인: 차원은 형태를 설명할 뿐 임베딩 공간의 식별 정보가 아닙니다. M2는 각 벡터와 함께 공급자/모델 지문을 저장하지 않습니다.

수정: 백필과 쿼리에 하나의 공급자 구성을 사용합니다. 공급자를 변경하려면 명시적으로 다시 구축하거나 마이그레이션해야 하며, `--embed-missing`은 의도적으로 null이 아닌 벡터를 덮어쓰지 않습니다.

회귀 테스트: 공급자 선택과 null 전용 백필을 테스트합니다. M3에서는 실험 산출물에 공급자 구성을 기록해야 합니다.

## B08 — 유효하지 않은 융합 설정이 실패 전에 작업을 수행했음

상태: 수정됨.

증상: 양수가 아닌 `rrf_k` 값이 RRF에서 거부되기 전에 공급자와 데이터베이스에 도달할 수 있었습니다.

근본 원인: 검증이 마지막 순수 융합 함수에만 있었습니다.

수정: 서비스 경계에서 빈 쿼리, `k`, `candidate_k`, `rrf_k`, 공급자 차원을 검증합니다. 하이브리드 도우미도 구성 요소 호출 전에 양수가 아닌 `rrf_k`를 거부합니다.

회귀 테스트: 매개변수화된 서비스 테스트는 모든 I/O 호출을, 호출되면 실패하는 함수로 교체합니다.

## B09 — 공급자 응답 순서를 암묵적으로 신뢰했음

상태: 수정됨.

증상: SDK 응답의 데이터 항목이 입력과 다른 순서로 도착하면 잘못된 벡터가 청크에 할당될 수 있었습니다.

근본 원인: 응답 인덱스를 사용하는 대신 응답 목록의 위치를 호출자 순서로 취급했습니다.

수정: 빠짐없이 고유한 인덱스인지 검증하고, 인덱스별로 매핑하며, 형태를 검증하기 전에 호출자 순서를 복원합니다.

회귀 테스트: OpenAI 공급자 테스트는 순서가 반대인 응답 항목을 제공하고 순서가 복원되기를 기대합니다. 중복되거나 불완전한 인덱스는 실패합니다.

## B10 — `create_all`을 마이그레이션으로 오해했음

상태: 문서화된 제한 사항.

증상: 이전의 기존 테이블 정의를 대상으로 `--create-schema`를 실행해도 누락된 열이 그대로 남았습니다.

근본 원인: SQLAlchemy 메타데이터 생성은 없는 객체를 생성할 뿐, 변경 계획을 세우지 않습니다.

수정: 부트스트랩을 새 스키마 전용 작업으로 설명합니다. 스키마를 발전시키려면 검토된 마이그레이션이나 일회용 데이터베이스를 사용합니다.

회귀 테스트: CLI 도움말과 M1.4/M2 명세에 이 경계가 명시되어 있습니다.

## B11 — 기본 후보군이 결과 제한과 같아졌음

상태: 수정됨.

증상: `candidate_k`를 생략하면 각 구성 요소에 `k`개의 후보만 요청하여, 합의된 후보를 RRF가 복구하기에 순위 깊이가 너무 얕았습니다.

근본 원인: 저수준 하이브리드 도우미의 최소 대체 값이 프로덕션 서비스 계약으로 유출되었습니다.

수정: 서비스는 `max(20, 4 * k)`를 계산하되 호출자가 `candidate_k`를 생략한 경우에만 적용하고, `candidate_k >= k`를 만족하는 명시적 값은 모두 그대로 유지합니다.

회귀 테스트: 서비스 구성 테스트는 `candidate_k`를 생략하고, `k=2`일 때 두 구성 요소 호출 모두 20 값을 기록한 다음 `k=6`일 때 24 값을 기록합니다.

## B12 — 실제 PostgreSQL 테스트가 SQL 완료 후 멈췄음

상태: 수정됨.

증상: 테스트 연결은 `pg_stat_activity`에서 사라졌지만, 샌드박스의 pytest 프로세스는 Python 실행기가 종료되는 동안 300초 동안 계속 실행될 수 있었습니다.

근본 원인: 테스트가 `localhost`를 해석하고 연결 가능성 확인과 테스트 작업을 두 개의 `asyncio.run` 이벤트 루프로 나눴습니다.

수정: 프로젝트 테스트 데이터베이스 픽스처는 루프백 URL만 허용하고, 호스트를 `127.0.0.1`로 정규화하며, 하나의 이벤트 루프에서 프로브와 임시 테이블 인수 테스트를 실행합니다.

회귀 테스트: 집중형 검색 테스트 모음에 실제 테스트가 포함되며 신속하게 종료됩니다.
