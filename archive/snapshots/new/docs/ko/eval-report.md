## 포트폴리오 결론

이 실행은 저장소가 격리된 코퍼스를 구축하고, 청킹×검색×랭커 행렬 전체를 실행하고, 불변 원문 범위를 채점하고, 사례별 순위를 보존하고, 유료 호출이나 코퍼스 변경 없이 로컬 지연 시간 예산을 강제할 수 있음을 증명합니다. M2의 두 어휘 랭커가 실제로 선택 가능하고 측정 가능하게 다르다는 것도 증명합니다.

의미론적 검색 품질, 사람이 승인한 골든 정답, 프로덕션 규모, 호스팅 지연 시간은 증명하지 **않습니다**. 벡터 품질은 결정론적 토큰 해시 기준선이고, 그 약점이 모든 하이브리드 실험군의 상한이 되며, 모든 골든 사례는 작성자 승인 대기 상태입니다. 이는 통과한 예산 뒤에 숨길 세부 사항이 아니라 결정을 멈추게 하는 한계입니다.

아키텍처적 함의와 운영 대응은 [architecture.md](architecture.md)와 [failure-analysis.md](failure-analysis.md)에 기록되어 있습니다.

## 골든 스위트 출처

스위트에는 에이전트가 선별한 후보 28개가 있습니다. 원문 범위를 가진 양성 사례 24개와 부재 사례 4개입니다. 양성 정답은 불변의 `(doc_id, source_sha256, [start, end))` 원시 파일링 좌표이며 두 청킹 실험군에서 동일하게 유지됩니다. 모든 사례는 작성자 승인 대기 중이고 `human_verified=false`입니다. 기계 검증을 사람의 검토로 제시해서는 안 됩니다.

분류 체계는 설계상 균형을 이룹니다. 카테고리는 `simple_lookup` 13개, `exact_number` 5개, `multi_hop` 6개, `absent` 4개로 나뉘고, 패싯은 `factual` 6개, `comparison` 6개, `risk` 6개, `policy` 5개, `numeric` 5개로 나뉘며, 양성 24개는 티커당 여섯 사례로 20개 파일링 전체를 인용합니다. M3.5부터 스위트는 `app/evals/curation.py`의 게이트 큐레이션 파이프라인으로만 성장합니다. 생성된 후보는 `m3s` 네임스페이스로 들어와 원문 바인딩·중복·span 폭 기계 게이트를 통과하고, 명시적으로 기록된 검수 결정을 거쳐야만 `m3c` id에 도달합니다.

이 구축 방식의 알려진 편향은 다음과 같습니다. 생성기가 파일링을 읽으면서 질문을 썼으므로 표현이 원문 어휘 쪽으로 쏠려 어휘 검색 점수가 낙관적으로 나올 가능성이 높습니다. span 입도 — 문장, 조각, 표 행 — 는 큐레이터가 선택했고 이것이 모든 매칭 규칙에서 "관련 있음"의 의미를 고정합니다. 그리고 단일 에이전트 계열이 모든 사례를 생성했으므로 그 생성기가 상상하지 못하는 실패 모드는 스위트에 없습니다. 후보 라운드 `data/golden/candidates/r1.json`은 첫 번째 편향을 검사하려고 일부러 원문 표현을 피해 바꿔 썼습니다.

## 해석

- 어휘 쿼리를 실행한 모든 실험군에서 BM25가 `ts_rank_cd`를 이겼습니다. 문서 빈도·포화·길이라는 코퍼스 통계는 정확히 커버 밀도가 볼 수 없는 것이고, 그 차이가 1200자에서 `0.520833` 대 `0.270833`으로 측정되었습니다.
- 완화된 `ts_rank_cd` 기준선은 이전 실행이 정확히 0을 측정했던 곳에서 이제 검색합니다. 그 비용은 후보의 폭입니다. 논리합 매칭이 P95 지연 시간을 180-291 ms로 밀어 올려 행렬에서 가장 느린 실험군이 되었습니다.
- 어휘 검색이 모든 곳에서 하이브리드 융합을 이겼습니다. RRF는 순위만 사용하므로 한 구성 요소가 약하다는 것을 알 수 없고, 더 강한 어휘 순위에 결정론적 벡터 순위를 융합하면 희석될 수밖에 없습니다.
- 500자 실험군이 더 이상 전면적으로 이기지 않습니다. 동작하는 어휘 랭커가 있으면 1200자 BM25 실험군이 가장 강하므로, 청킹과 랭킹은 상호작용하며 어느 쪽도 단독으로 조정할 수 없습니다.
- 결정론적 공급자는 여전히 배관과 재현성의 기준선이지 의미론적 품질이 아닙니다. 어휘 대 어휘 비교만이 임베딩과 무관합니다.

```bash

```

## OpenAI 명시적 동의 게이트

OpenAI 임베딩 요청은 실행되지 않았습니다. 작성자의 명시적 비용 승인과 자격 증명/모델 접근 확인 후, 별도 실험을 다음으로 실행하십시오.

```bash
OPENAI_API_KEY="your-key" uv run python -m app.evals --provider openai --target-text-chars 500 1200 --strategies lexical vector hybrid -k 5 --candidate-k 20 --rrf-k 60 --budget-queries 200 --artifact-dir data/eval_runs
```

토큰당 4자 근사로 추정 입력은 약 385.5만 토큰입니다. 2026-08-12에 확인한 공식 [`text-embedding-3-small` 가격, 입력 토큰 100만 개당 $0.02](https://developers.openai.com/api/docs/models/text-embedding-3-small)를 사용하면 날짜가 명시된 계획 추정치는 약 **$0.08**입니다. **$0.10** 상한을 승인하고 실행 직전에 현재 가격을 다시 확인하십시오. 실제 공급자 토큰화, 재시도, 청구가 최종 비용을 결정합니다.

## 결정과 미해결 게이트

이 결정론적 실행을 재현 가능한 오프라인 기준선으로 유지하십시오. 어휘 랭커 비교는 임베딩과 무관하게 그 자체로 성립합니다. 그럼에도 프로덕션 기본값은 `ts_rank_cd`로 남으며, BM25 승격은 측정의 자동 귀결이 아니라 작성자의 명시적 결정입니다. 남은 게이트는 모든 골든 사례의 작성자 검토와 명시적으로 승인된 별도 라벨의 의미론적 공급자 실행이며, 완료된 기계 검사가 어느 쪽도 함의하지 않습니다.
