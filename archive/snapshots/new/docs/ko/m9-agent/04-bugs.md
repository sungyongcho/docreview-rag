# M9 버그 — 남겨둘 가치가 있는 실패들

## B1 — 엄격 모델이 모델 자신의 JSON을 거부했다

`AgentAnswer`는 엄격한 동결 베이스를 상속하는데, 엄격 검증은 JSON 배열을 튜플 필드로 강제 변환하기를 거부한다. 문법적으로 완벽한 `final_answer` 페이로드가 전부 무효로 거부됐고, 루프는 애초에 틀리지 않았던 답을 재시도하느라 예산을 태웠다. 수정: 루프는 provider JSON을 `strict=False`로 검증한다 — 전송 계층의 강제 변환은 느슨하게 두되 `extra="forbid"`는 여전히 낯선 키를 거부한다. 교훈은 일반화된다: 엄격함은 계약의 것이지, 와이어 포맷의 것이 아니다.

## B2 — 거부된 인용 하나가 실행 전체를 삼켰다

첫 인용 게이트 구현은 최종 답이 검색되지 않은 청크를 인용하는 순간 종결적 실패를 반환했다. 그것은 모델의 실수 하나를 죽은 실행으로 바꾼다. 이제 게이트는 문제가 된 chunk id를 지목하는 관찰로 거부를 되돌려 보내고, 모델은 같은 예산 안에서 다시 검색하거나 `NOT_IN_DOCS`로 답할 수 있다.

## B3 — 실패하는 도구가 모델에게 보이지 않았다

초기 dispatch 초안은 도구 예외를 그대로 전파시켜 실행을 죽이고 모델에게 아무것도 알리지 않았다. 수동 테스트의 이후 턴들에서 모델은 일어난 적 없는 도구 출력을 "기억"하기 시작했다. 이제 모든 실패 계급은 명시적 `ERROR:` 관찰이 된다 — 모델이 무슨 일이 있었는지 추측하게 두어서는 안 된다.

## B4 — 데모 스크립트가 가질 수 없는 근거를 인용했다

첫 오프라인 CLI 스크립트는 결정론적 provider가 그럴듯한 chunk id와 함께 `SUPPORTED`로 답하게 했다. 루프는 그것을 올바르게 거부했다 — 스크립트된 provider는 라이브 검색이 어떤 chunk id를 돌려줬는지 알 수 없다. 데모는 이제 `NOT_IN_DOCS`로 답하며, 그것이 실제 근거 없이 근거 게이트가 걸린 에이전트가 할 수 있는 정직한 진술이다.
