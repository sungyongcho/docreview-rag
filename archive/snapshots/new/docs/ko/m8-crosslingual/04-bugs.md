# M8 버그

이 파일은 이 모듈이 실제로 밟은 함정과 각각에 대한 좁은 수정을 기록한다. 앞으로 있을 법한 기능의 목록이 아니다.

## B01 — 골든 디렉터리를 적재하니 쌍둥이가 한 배치에 들어갔다

**증상:** `load_golden_cases("data/golden")`이 중복 정답 span 식별자를 이유로 `GoldenDataError`를 던졌다. `retrieval_ko.json`이 `retrieval.json` 옆에 생기자마자였고, 두 파일은 각각으로는 유효했는데도 그랬다.

**근본 원인:** 로더는 디렉터리를 받아 그 안의 모든 `*.json`을 파일명 순서로 한 배치에 병합하고, `_validate_unique_cases`는 *한 배치 안의 사례들에 걸친* 중복 정답 span 식별자를 거부한다. 쌍둥이는 의도적으로 모든 span을 공유하며 — 그 공유된 span이 동등성 숫자에 의미를 주는 물건이다 — 따라서 병합 적재는 이 규칙이 금지하는 바로 그 경우다.

**수정:** 두 스위트를 절대 디렉터리로 적재하지 않는다. `load_bilingual_suites`는 `load_golden_cases`를 두 번 따로 호출하고 그 뒤에 짝을 검증한다. 각 파일은 여전히 로더의 완전한 매니페스트, SHA-256, 경계, 눈으로 확인 가능한 증거 검증을 받고, 영어 파일은 손대지 않는다.

**가드:**

```bash
uv run pytest tests/crosslingual/test_01_bilingual.py -k "same_spans" -q
```

## B02 — 쌍둥이 검증기가 원인 대신 증상을 이름 붙였다

**증상:** 저작 중에 영어 질문을 한국어 사례에 붙여 넣자 `m3c-12 Korean question contains no Hangul`이 나왔고, 읽는 사람은 번역된 적이 없다는 것이 유일한 잘못인 사례에서 인코딩 문제를 찾아 헤맸다.

**근본 원인:** 문자 규칙 검사가 차이 검사보다 먼저 돌았다. "한글 없음"은 번역되지 않은 복사본에 대해 참이지만 그것은 2차 결과이고, 1차 사실은 두 질문이 같은 문자열이라는 것이다.

**수정:** 검사 순서는 계약의 일부다. `validate_twin_cases`는 대소문자와 공백을 정규화한 질문을 먼저 비교해 `twins share one untranslated question`을 던지고, 그 뒤에야 한글 규칙을 적용한다. 나중의 리팩터링이 순서를 조용히 뒤섞지 못하도록 소스에 주석으로 순서를 못 박아 둔다.

**가드:**

```bash
uv run pytest tests/crosslingual/test_01_bilingual.py -k "untranslated" -q
```

## B03 — routed 처리가 테스트가 가짜로 만든 리트리버를 지나쳐 갔다

**증상:** `make_retriever`를 스텁으로 바꾼 테스트가 실험군의 처리가 `routed`일 때 여전히 실제 데이터베이스 연결을 열려고 했고, 단언 실패가 아니라 세션 오류로 실패했다.

**근본 원인:** `direct`와 `translated` 처리는 `make_retriever` 위에 세워지지만 `routed`는 아니다. 라우팅은 운영 질의 경로의 성질이므로 routed 래퍼는 `retrieve()`를 `route_by_language=True`로 직접 호출한다. 그것이 이 실험군의 요점이고, 동시에 테스트가 갈아 끼운 팩토리를 결코 통과하지 않는다는 뜻이기도 하다.

**수정:** 소스에는 수정이 없다. 실험군은 쓰인 그대로 옳다. 대신 테스트 계약이 바뀌었다. routed 실험군에서 검색 경계를 가짜로 만들려면 `retrieve`도 함께 가짜로 만들어야 한다. routed 테스트는 `retrieve`가 받은 인자를 단언하는데, 이것이 라우팅이 실제로 요청됐다는 가장 깔끔한 증명이기도 하다.

**가드:**

```bash
uv run pytest tests/crosslingual/test_02_crosslingual.py -k "routed" -q
```

## B04 — "죽은" lexical 실험군은 완전히 죽어 있지 않았다

**증상:** 커버리지 진단의 초기 초안이 한국어의 후보 0건 비율을 100%로 단언했다가 실제 코퍼스에서 실패했다.

**근본 원인:** 반도체 공시에 관한 한국어 질문은 본래 문자 혼용이다. `AMD의 7nm 공급 위험`은 티커, 단위, 숫자를 라틴 문자로 싣고 있고 영어 tsquery는 그 렉심들을 기꺼이 매칭한다. 붕괴는 부분적이며, 얼마나 부분적인지는 상수가 아니라 이 질문 집합의 성질이다.

**수정:** `lexical_candidate_coverage`는 그 비율을 측정값으로 보고한다. 후보 0건 사례 수, 비율, 평균 후보 수, 그리고 비어 있던 사례의 ID다. 어떤 테스트도 특정 비율을 단언하지 않는다. 오프라인 테스트는 동작이 알려진 스크립트된 실험군을 돌리고, 실제 비율은 측정 실행이 만들어 내는 숫자다.

**가드:**

```bash
uv run pytest tests/crosslingual/test_02_crosslingual.py -k "lexical_coverage" -q
```

## B05 — 해시 충돌이 "직교" 벡터를 살짝 비직교로 만들었다

**증상:** 결정론적 쌍둥이 질의 벡터에 대해 `cosine == 0.0`을 단언한 테스트가 `1e-2` 언저리 값으로 실패했다.

**근본 원인:** 결정론적 공급자는 토큰을 384개 버킷으로 해싱한다. 한국어 질문과 영어 쌍둥이는 토큰을 거의 공유하지 않지만, 실제 어휘를 384개 버킷에 넣으면 충돌이 나서 무관한 토큰이 같은 차원에 떨어지고 작은 양의 내적을 만든다. 이 공급자는 한글 어절도 토큰으로 유지한다 — 토크나이저가 NFKC로 정규화하고 `[^\W_]+`에 매칭한다 — 그래서 한국어 쪽도 빈 벡터가 아니다.

**수정:** 정확한 0이 아니라 0에 가까움을 단언한다. 구조적 주장은 "이 공간은 두 언어를 관계 짓지 않는다"이고, 그 주장의 정직한 테스트는 등식이 아니라 작은 상한이다. 나중에 누가 조이지 못하도록 같은 논리를 진단 자신의 docstring에도 적어 둔다.

**가드:**

```bash
uv run pytest tests/crosslingual/test_02_crosslingual.py -k "twin_alignment" -q
```

## B06 — 죽은 영어 슬라이스가 완벽한 동등성처럼 보였다

**증상:** 초기 초안에서 영어 recall이 `0.0`, 한국어 recall이 `0.0`인 실험군이 동등성 판정 `PASS`를 만들어 냈다. `0/0`이 `1.0`으로 강제 변환됐기 때문이다.

**근본 원인:** 분모가 0이면 비율은 정의되지 않는데, 기본값 `1.0`은 진실이 "어느 실험군도 아무것도 검색하지 못했다"일 때 "두 언어가 일치한다"로 읽힌다.

**수정:** `ParityMetric.ratio`는 `float | None`이고, `None`은 정의되지 않음을 뜻하며, 정의되지 않은 게이트 대상 비율은 실패로 기록된다 — 게이트는 fail-closed다. `parity_markdown`은 이것을 숫자가 아니라 글자 그대로의 단어 `undefined`로 렌더링하므로 표를 통과한 결과로 읽을 수 없다.

**가드:**

```bash
uv run pytest tests/crosslingual/test_05_parity.py -k "zero" -q
```
