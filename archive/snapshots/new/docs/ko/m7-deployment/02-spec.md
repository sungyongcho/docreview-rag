# M7 명세

이 문서는 M7의 규범 문서입니다. 로컬 릴리스 산출물이 주장할 수 있는 내용과 외부 배포 없이는 명시적으로 입증되지 않은 상태로 남아야 하는 내용을 정의합니다.

## 1. 의존성과 순서

- M7.1 단계에는 M6.3 단계가 필요합니다.
- M7.2 단계에는 M7.1 단계가 필요합니다.
- M7.3 단계에는 M7.2 단계가 필요합니다.
- 문서는 눈에 보이게 `M7.1 -> M7.2 -> M7.3` 순서를 유지해야 합니다.

## 2. 미리 준비된 모드를 기본으로 하는 정책

릴리스 진입점은 `canned`을 기본값으로 사용하고 데이터베이스나 공급자를 전혀 호출하지 않아야 합니다. 환경에 공급자 키가 있어도 모드가 바뀌어서는 안 됩니다. UI와 `/release` 리소스에서는 자격 증명을 노출하지 않고 활성 모드를 확인할 수 있어야 합니다.

## 3. 선택적 공급자 정책

- 공개 브라우저는 키를 입력받거나 저장하거나 렌더링해서는 안 됩니다.
- 선택적 OpenAI 액세스는 운영자가 제공한 서버 환경 비밀 값을 사용해야 합니다.
- 키는 명시적인 `runtime` 모드에서만 활성화되어야 합니다.
- 공급자 요청은 원격 저장을 끄고 엄격한 구조화 출력을 사용해야 합니다.
- 비밀 값은 영속화 및 로깅 마스킹 대상으로 전달해야 합니다.
- 사용자 자격 증명, 계정 생성, 실제 호출, 외부 게시는 M7 인수의 선행 조건이 아닙니다.

## 4. 비용 정책

모든 선택적 공급자 워크플로에는 양의 input/output 토큰 제한, 명시적인 100만 개당 가격, 유한한 음이 아닌 예상 비용 상한이 있어야 합니다. 가격을 알 수 없으면 안전하게 실패해야 합니다. 현재 기본값은 입력 토큰 12,000 개, 출력 토큰 600 개, `$0.01`입니다. 가격에는 날짜를 명시하고 승인된 실행 전에 다시 확인해야 합니다.

## 5. 요청 제한 정책

공개 단일 워커 산출물은 POST에 준하는 작업에 이동식 분당 및 일당 제한을 적용해야 합니다. 클라이언트 상태에는 유한한 상한이 있어야 합니다. 프록시 헤더 신뢰를 명시적으로 활성화하지 않는 한 직접 연결한 클라이언트 주소를 사용해야 합니다. 429 응답에는 재시도 간격과 남은 한도가 포함되어야 합니다.

인프로세스 제한기를 분산 보호 수단으로 제시해서는 안 됩니다. 여러 워커 또는 복제본으로 공개 확장하기 전에 공유 제한기가 필요합니다.

## 6. HTTP 및 변경 정책

공개 수집은 기본적으로 비활성화해야 합니다. 보안 헤더는 성공 응답, 타입이 지정된 애플리케이션 오류, 읽기 전용 403 응답, 요청 제한 429 응답을 감싸야 합니다. 프레임을 차단하는 헤더가 문서에 기술된 Hugging Face 임베딩 경로를 막아서는 안 됩니다.

## 7. 컨테이너 및 Space 정책

- Space 메타데이터 템플릿은 `sdk: docker`와 `app_port: 7860`을 선언해야 합니다.
- 이미지 구성은 실행 UID 1000, 노출 포트 7860, 상태 확인, Uvicorn 워커 하나 고정을 포함해야 합니다.
- 빌드 시 잠긴 의존성과 선택적 데모 추가 의존성을 설치해야 합니다.
- Compose는 PostgreSQL을 유지하면서 애플리케이션 컨테이너에 no-new-privileges, 삭제된 capabilities, 읽기 전용 루트 파일 시스템, 쓰기 가능한 `/tmp`를 적용해야 합니다.

## 8. 검증 정책

M7을 완료하려면 집중 release/demo/API 테스트, 채워진 저장소의 전체 오프라인 스위트, Ruff, 소유 범위 형식 검사, documentation/link 동기화, 잠금 검증, Compose 검증, 컨테이너 빌드, 로컬에서 미리 준비된 health/UI 스모크 테스트, 새로운 환경을 사용하는 임시 클린 아카이브가 필요합니다.

클린 아카이브에는 `.env`, 무시된 코퍼스 HTML, 캐시 또는 가상 환경을 복사해서는 안 됩니다. 외부 자격 증명과 외부 계정 변경은 계속 제외해야 합니다.

## 9. 언어와 증거

모든 명령, 코드 블록, 코드 주석, 독스트링은 영어로 작성해야 합니다. 개수는 이전 단계의 합계로 계산하지 말고 측정된 명령 출력에서 복사해야 합니다. 골든 데이터는 에이전트가 선별한 상태로 남으며 절대 사람이 검증한 것으로 표시해서는 안 됩니다.
