## 수정 결과

### H01 — 번역 라우팅 오류 해결

사용자의 실제 Chrome 화면에서 영어 NVIDIA 질문, 자동 공시 범위, 한국어 프리셋과 `Query routing failed for ko (QueryTranslationError)` 기록을 확인했다.

- 한국어 프리셋이 문서 언어 `ko`를 암묵적으로 주입하던 경로를 제거했다. 프리셋은 검색 설정만 선택하고, 공시 언어는 실제 기업·공시 범위 또는 명시적 언어 필터로 정한다. 한국어 프리셋과 SEC·영어 문서 필터도 함께 사용할 수 있다.
- 조회와 검토 모두 언어별 라우팅이 켜져 있고 질문 언어와 대상 공시 언어가 다를 때만 번역한다. 같은 언어의 조회에는 번역 공급자 자체가 필요하지 않다.
- 라우팅 프롬프트가 원래 언어를 요구하면서 출력 스키마는 대상 언어를 요구하던 모순을 제거했다. `translated_query`와 지정된 `target_language`를 명시하며, 기존 번역 함수의 원래 언어 계약은 유지했다.
- 번역된 검색어가 있으면 원문 질문의 문자 종류만으로 해당 키워드 검색 경로를 건너뛰지 않는다. 잘못된 언어·스키마·거부 응답은 여전히 오류로 종료한다.
- 영한 프리셋 안내와 설정 문서도 이 의미에 맞췄다. 기존 실패 대화는 기록이므로 수정하거나 성공 응답으로 바꾸지 않았다.

실제 DEV에서 같은 영어 질문과 한국어 프리셋으로 `/retrieve`를 호출해 HTTP200, `sec`/`NVDA`/`en`, 실제 근거 5개와 영어 BM25 후보 30개를 확인했다. 임베딩 공급자가 `deterministic`임을 먼저 확인했고 모델 생성은 호출하지 않았다. 실제 반환 문서는 NVDA-FY2021·FY2023·FY2024였다. 이는 검색 경로 검증이며 답변 생성이나 의미 검색 품질의 측정이 아니다. 원래 4.26초 실패의 공급자 내부 상태는 기록에 없으므로 특정 공급자 오류로 단정하지 않는다.

### H06 — 스크롤바 UX와 CSS 반영

문서 좌측 메뉴와 목차의 스크롤바는 평소 투명하게 유지하고, hover·영역 내 포커스 때 얇게 표시한다. 고정 gutter로 표시 전환 시 폭이 바뀌지 않으며, 고대비 모드는 기본 스크롤바를 사용한다. 700px 이하에서는 기존 모바일 동작을 유지한다. 이미지 뷰어의 스크롤바는 변경하지 않았다.

실제 브라우저에서 1200×750 화면의 사이드바 폭은 기본·hover·키보드 포커스 모두 218px였다. 기본 scrollbar-color는 투명, Light hover는rgb(98,98,98), Dark hover는rgb(170,170,170)이었다. 휠로 사이드바만 420px 이동했고 문서 본문 위치는 0이었다. Tab으로 마지막 Ollama 항목에 접근했고, 포커스가 빠지면 다시 투명해졌다. 고대비에서는auto, 390px 화면에서는 기존auto gutter이며 문서 폭375px로 가로 넘침이 없었다. 업데이트한18081 개발 기록 화면에서도thin·투명·stable·overflow:auto와15개 문서 링크를 확인했다.
