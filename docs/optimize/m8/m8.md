# Module 8

- `M8.1`: 영어 골든 스위트와 한국어 쌍둥이를 같은 answer span 위에 묶어 로드·검증하는 코드다(`app/evals/bilingual.py`, `data/golden/retrieval_ko.json`). `validate_twin_cases`의 필드 동일성·id 집합·스크립트 규칙 검사가 이 체크포인트의 산출물 자체이고 실행은 `28`개 쌍을 실행당 한 번 로드하는 경로라, 측정된 병목이 없어 현재 구조를 유지한다. `BilingualSuite.pairs()`가 호출마다 id 인덱스를 다시 만드는 것도 유지한다 — 테스트가 `BilingualSuite`를 생성자로 직접 만들기 때문에 `en`과 `ko`가 이미 같은 순서라는 가정을 코드에 넣으면 로더 밖에서 조립된 스위트가 조용히 잘못된 쌍을 만든다.
  - 완료 검수에서 실행 동작을 바꾸지 않는 정합성 수정 3건을 반영했다: `load_bilingual_suites`가 버리던 `validate_twin_cases`의 반환 pairs를 그대로 사용해 정렬 1회와 ko 인덱스 재구성을 제거했고(검증기는 `sorted(en_index)` 순서로, 기존 코드는 `sorted(en_cases, key=id)` 순서로 쌓아 두 경로의 `en`·`ko` 순서 계약이 동일하다), 그 id 순서 보장을 `validate_twin_cases` 요약줄에 명시했으며, `_normalized`에 [docstring.md](../docstring.md) 기준 한 줄 docstring을 추가했다.
- `M8.2`: 실험군 문법, 질의 경로 진단, 렌더링, 측정 명령을 정의하는 코드다(`app/evals/crosslingual.py`, `app/retrieval/sbert.py`의 `MULTILINGUAL_SBERT_MODEL`). `CrosslingualArm.__post_init__`의 거절 규칙과 `to_config()`의 provenance, `twin_query_alignment`·`lexical_candidate_coverage` 진단은 전부 "측정된 숫자를 무엇에 귀속시킬 수 있는가"라는 계약이고, 실행량은 기본 행렬 `6`개 실험군과 언어별 `28`개 질의(coverage probe `56`회)라 캐시나 배치를 도입할 대상이 아니어서 현재 구조를 유지한다. `parity_pairs`의 identity 키가 provider와 `k`를 포함하지 않는 것도 유지한다 — CLI는 실행당 provider를 고정하고, 서로 다른 provider의 run이 섞여 들어오면 `assess_parity`의 config 동일성 검사가 조용히 비교하는 대신 `ValueError`로 닫는다. `--gate` 실행 가능성 검사가 인덱싱 뒤에 오는 것도 유지한다: 앞당기려면 `parity_pairs`의 쌍 짓기 규칙을 arms 위에 한 번 더 구현해야 하고, 그 중복이 실제 게이트 판정과 어긋나는 쪽이 인덱싱 한 번보다 위험하다.
  - 정합성 수정 2건: `_cosine`과 `_positive_int`에 한 줄 docstring을 추가했고, DB engine·유료 provider·artifact 쓰기·영속화 경계를 모두 여는 `_run_cli`에 [docstring.md](../docstring.md) 기준 NumPyDoc(`Parameters`, `Returns`, `Raises`, `Notes`)을 추가했다.
- `M8.3`: 질의 언어 감지, 라우팅 스위치, 번역 경계를 만드는 코드다(`app/retrieval/language.py`, `translate.py`, `service.py`, `app/config.py`). `contains_hangul`이 문자마다 `ord()`를 최대 세 번 호출하지만 대상은 질의 한 줄이고 독립 측정이 없어 그대로 두며, `retrieve`가 `route_by_language=None`을 `Settings.query_language_routing`으로 해석하고 `skip_lexical`을 lexical 컴포넌트 안에서 빈 리스트로 반환하는 위치도 `ComponentRankings`에 빈 lexical 랭킹이 그대로 기록되게 하는 관측 계약이라 유지한다. 실패 시 원문으로 되돌아가지 않는 `translate_query`의 fail-closed 계약과 provider 주입 방식도 유지한다. 환경에서 `query_language_routing`이 켜지면 M8.2의 `direct` hybrid 실험군도 조용히 라우팅되던 비교가능성 문제는 검수 후속으로 닫았다: `make_retriever`의 hybrid 분기가 `retrieve`에 `route_by_language=False`를 명시적으로 고정한다(시그니처 변경 없음). 묶인 실험군은 환경 플래그와 무관하게 결정론적이고, 라우팅 축은 M8의 `routed` 래퍼가 하는 명시적 `retrieve` 호출로만 실험에 들어온다.
  - 정합성 수정 1건: `translate_query`의 `Raises`에 실제로 발생하는 `ValueError`(공백 질의)를 추가했다. 기존 `Raises` 절이 `QueryTranslationError`만 선언하고 있어 절 자체가 불완전했다.
- `M8.4`: 동등성 지표와 그 게이트를 정의하는 코드다(`app/evals/parity.py`, `app/evals/crosslingual.py`의 `parity_pairs`·`gated_assessments`). 지표 `3`개를 실험군 쌍마다 한 번 훑는 선형 계산이고, 영어 슬라이스가 `0`일 때 비율을 fail-closed로 닫는 규칙, 바닥 근처의 `math.isclose` 허용, 언어별 `language_regression`의 `0.05` 허용 오차가 전부 판정 계약이라 현재 구조를 유지한다. `ParityAssessment.metric()`의 선형 탐색도 metric이 세 개뿐이라 dict 인덱스를 추가하지 않는다.
  - 정합성 수정 2건: `_config_identity`와 `_case_ids`에 [docstring.md](../docstring.md) 기준 한 줄 docstring을 추가했다.
