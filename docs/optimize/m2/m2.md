# Module 2

- `M2.1`: 검색 결과의 근거·출처 계약과 결정론적 정렬을 정의하는 코드이며, 필수 검증 외에 측정된 병목이나 리팩터링 필요성이 없어 현재 구조를 유지한다.
  - 실행 동작은 바꾸지 않고 패키지·모듈 docstring과 `sort_hits` NumPyDoc을 보완했으며, M2.5의 대체 점수 top-k가 같은 출처 동점 키를 사용하도록 내부 키 함수만 추가했다.
- `M2.2`: 임베딩 공급자 검증, 배치 처리, 네트워크와 트랜잭션 분리, stale 쓰기 방지를 구현한 코드이며, 각 단계가 안전성 계약에 필요하고 측정된 병목이 없어 현재 구조를 유지한다.
  - 유효한 공급자 출력의 정적 계약은 `float`으로, 실제 값 검증은 `isinstance(..., Real)`로 분리해 Pylance 정합성을 맞췄다. `Result[Any].rowcount` 타입 추론을 함께 수정하고 모듈 및 최상위 함수 NumPyDoc을 보완했다.
- `M2.6`: 선택적 provider의 유무와 무관하게 같은 정렬·절단 경로를 지나야 향후 ablation의 비교 조건이 유지되므로 현재 구조를 유지한다.
  - provider 경로의 heap top-k는 후보 `20`개와 `top_k=5`에서 `38.787µs`에서 `18.291µs`로 빨랐지만, provider 없는 경로와 다른 알고리즘이 되어 지연시간 비교에 정렬 차이를 섞으므로 채택하지 않았다. 공급자 점수의 정적 계약은 `float`, 런타임 검증은 `Real`로 분리했으며 실행 동작은 바꾸지 않고 모듈과 `rerank_hits` NumPyDoc만 보완했다.
- `M2.8`: pgvector extension을 먼저 활성화한 뒤 SQLAlchemy 스키마를 생성하는 순서 자체가 PostgreSQL 타입 해석에 필요한 안전성 계약이며, 두 필수 작업 외에 줄일 실행 단계가 없어 현재 구조를 유지한다.
- `M2.9`: `content_tsv`에서 파생한 코퍼스 통계를 원자적으로 재구축하고 PostgreSQL 안에서 BM25를 계산하는 코드이며, 전체 재구축은 청크 변경 뒤에만 실행되고 질의 경로는 실제 청크 `9,172`개·term 행 `517,893`개에서 `k=20` 검색 40회 기준 중앙값 `15.736ms`, P95 `16.246ms`로 측정되어 현재 구조를 유지한다.
- `M2.10`: 로컬 sentence-transformer를 지연 로딩하고 동기 추론을 워커 스레드로 옮긴 뒤 공유 임베딩 검증을 통과시키는 코드이며, 로딩 캐시·빈 배치 단축·출력 변환이 각각 선택 의존성·이벤트 루프·저장 경계에 필요하고 독립 전후 벤치마크가 없어 성능 향상을 주장하지 않은 채 현재 구조를 유지한다.
  - `_SentenceEncoder`와 `_EmbeddingMatrix` Protocol로 지연 로딩 객체의 정적 계약을 표현해 실행 동작을 바꾸지 않고 Pylance의 `encode`·`tolist` 멤버 오류를 제거했다. 이 Protocol 쌍은 이후 `R1-1`에서 `Callable` 반환 클로저로 대체됐다.
- `M2.11`: 융합이 만든 후보만 cross-encoder로 재채점하고 검증된 점수로 결정론적 top-k를 만드는 코드이며, 후보 쌍 생성·float 정규화·불변 hit 복사는 순서와 공급자 출력 계약에 필요하고 별도 전후 벤치마크가 없어 현재 구조를 유지한다.
  - `_CrossEncoderModel` Protocol로 `predict` 계약을 표현하고, CLI의 `--rerank`가 실제 공급자를 서비스에 전달하도록 배선한 뒤 `_run` 회귀 테스트로 보호했다. 이 Protocol도 이후 `R1-1`에서 클로저로 대체됐다.
