# Module 4

이 문서는 M4.1과 M4.4의 검수 결과다. 동작 변경과 측정 근거는 [M4.2 비밀 편집](m4-2.md)과 [M4.3 누적 provider 예산](m4-3.md)에 기록한다.

- `M4.1`: strict schema·provider 결과·최대 1회 repair 경계이며 실제 요청 지연이 지배하고 두 번의 고정 시도와 fail-closed 판정은 모두 필요한 계약이라 현재 구조를 유지한다.
  - 누락된 모듈 docstring과 OpenAI response-format 타입을 복원하고, injected client를 `object` 입력 뒤 최소 Protocol로 좁혀 offline fake와 실제 SDK 경계를 함께 표현했다.
  - `strict_response_format` 캐시는 스키마별 약 `0.13–0.27ms`를 줄였지만 네트워크 호출 앞의 절대 이득이 작고 model rebuild 뒤 stale schema와 mutable 반환 격리 비용이 있어 채택하지 않았다. 최대 두 항목을 소비하는 deterministic queue의 `deque` 전환도 실제 크기에서 더 빠르지 않아 유지했다.
- `M4.4`: strict JSON-schema 재작성과 바깥 validate-repair 방어를 결합한 경계이며 schema 생성은 요청당 한 번, 재귀 대상은 작은 모델 정의라 별도 최적화를 적용하지 않았다.
  - strict parse의 `json.loads → json.dumps → model_validate_json` 경로는 중복 키·비유한 수 거부와 JSON-mode tuple 변환을 함께 지킨다. Python 객체를 바로 `model_validate(strict=True)`에 넘기는 후보는 정상 citation 배열을 `tuple_type`으로 거부해 채택하지 않았다.
