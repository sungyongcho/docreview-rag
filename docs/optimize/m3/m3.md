# Module 3

이 문서는 M3.1–M3.3의 검수 결과다. 상세 변경과 측정 근거는 [M3.4 어블레이션 러너](m3-4.md)와 [M3.5 골든 큐레이션](m3-5.md)에 기록한다.

- `M3.1`: 골든 계약(`types.py`)은 동결 값 객체와 검증기만으로 구성되어 측정할 병목이 없고, 로더(`loader.py`)는 문서당 1회 바이트 읽기·SHA-256 캐시를 이미 갖추고 있어 현재 구조를 유지한다. 실측으로 28케이스·34스팬·20문서 전체 로드+검증이 약 `75ms`(재실행 약 `69ms`)라 추가 최적화 대상이 아니다.
  - `validate_golden_sources`의 들여쓰기 결함을 수정했다. 해시·경계·가시성 검사가 문서 캐시 적재 분기 안에 들여쓰여 있어, 같은 문서를 인용하는 두 번째 스팬부터 세 검사가 생략되고 직전 스팬의 `evidence` 값으로 가시성이 판정됐다. 세 검사를 스팬 단위로 내려 모든 스팬이 해시·경계·가시성 관문을 통과하게 했고, 34스팬이 20문서를 공유하는 실제 골든셋에서 이 경로가 매 로드마다 실행됨을 위 실측으로 확인했다.
  - `_read_json`의 반환 타입 `Any`를 `object`로 바꿔 `ANN401`을 해소했다. 호출부는 모두 `isinstance`로 좁혀 쓰므로 동작 변화가 없다.
  - 예외 메시지의 `corups` 오타를 `corpus`로 수정했다.
- `M3.2`: 점수 계산(`scoring.py`)은 순수 산술(스팬 IoU, 지표 집계)이며 28케이스 규모에서 측정된 병목이 없어 현재 구조를 유지한다.
- `M3.3`: 회귀 가드(`regression.py`)는 지표 3개의 비교 연산과 DB 왕복이 지배하는 코드라 로컬 최적화 대상이 없어 현재 구조를 유지한다.
  - `RegressionTolerances.__post_init__`의 placeholder docstring을 실제 계약 설명으로 교체해 `D400`/`D403`을 해소했다.
  - 중첩 헬퍼 `_validate_config_keys`의 인자 타입 `Any`를 `object`로 바꿔 `ANN401`을 해소했다. 본문이 `isinstance` 분기로만 값을 다루므로 동작 변화가 없다.

게이트 기준: `ruff check`·`ruff format --check`, `tests/evals` `131`개, 실제 loopback PostgreSQL, 직접 `python -m app.evals.retrieval_eval` 실행을 통과했다. M3.5 완료 시 `tests/evals`를 pyright 제외에서 제거했고 전체 `app tests scripts`가 basedpyright `0 errors`를 통과했다.
