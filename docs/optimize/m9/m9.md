# Module 9

- `M9.1`: 에이전트 경계의 값 객체와 하나의 tool registry를 정의하는 코드다(`app/agent/types.py`, `tools.py`, `registry.py`, `__init__.py`). `StrictAgentModel`의 `extra="forbid"`·`frozen`·`strict`, `AgentStep.observations_match_calls`의 call id 유일성과 이름 대조, `AgentAnswer.validate_label_contract`, `AgentCitation`의 `start_char`·`end_char`·`source_sha256` 전체 identity가 이 체크포인트의 산출물 자체이고 실행량은 한 번의 run에서 최대 `max_iterations`(기본 `8`)회 검증이라, 측정된 병목이 없어 현재 구조를 유지한다. `ToolRegistry.specs()`와 `manual()`이 호출마다 JSON schema를 다시 만드는 것도 유지한다 — 둘은 `run_agent` 진입에서 각각 한 번만 호출되고, registry는 등록 후 불변이 관례일 뿐 강제되지 않으므로 캐시를 넣으면 등록 순서에 따라 모델이 읽는 매뉴얼과 실제 schema가 조용히 어긋난다.
  - 완료 검수에서 실행 동작을 바꾸지 않는 정합성 수정 1건을 반영했다: `tools.py`에 `safe_runtime_error`를 신설해 loop와 MCP server가 공유하는 시크릿 안전 오류 투영의 소유자를 하나로 모았다([refactor] 절 참조).
- `M9.2`: provider turn 경계와 usage 회계를 정의하는 코드다(`app/agent/provider.py`). `ToolCallingProvider.turn`이 `_request`를 감싸 단조 시계로 지연을 재고 역행을 `ValueError`로 닫는 구조, `ProviderTurn.unique_call_ids`, `OpenAIToolProvider`의 `max_retries=0`·`store=False`·usage 부재 거절은 전부 "청구된 요청 하나가 정확히 agent step 하나로 표현되는가"라는 계약이라 현재 구조를 유지한다. `_turn_tool_calls`가 `getattr` 체인으로 SDK 응답을 읽는 것도 유지한다 — SDK item 타입을 정적으로 좁히면 `function_call` 이외 항목이 추가될 때 조용히 깨지는 대신, 현재 코드는 알 수 없는 item을 건너뛰고 빈 `call_id`·`name`은 `ToolCall` 검증이 거절해 loop의 `provider_error`로 닫힌다.
  - 정합성 수정 1건: `_turn_tool_calls`에 [docstring.md](../docstring.md) 기준 한 줄 docstring을 추가했다.
- `M9.3`: Thought → Tool → Observation 루프와 fail-closed 예산을 구현하는 코드다(`app/agent/loop.py`). 예산 회계의 사전 검사(`total_input >= max_total_input_tokens` 또는 `remaining_output <= 0`)와 응답 후 초과 검사가 비대칭인 것을 유지한다 — 사후 검사는 이미 청구된 turn을 step으로 기록한 뒤 `budget_exceeded`로 닫으므로, 예산을 넘긴 turn이 `final_answer`를 실어 와도 답이 채택되지 않는다. `_dispatch`의 5단계 실패 경로(lookup·검증·실행·직렬화·evidence 추출)가 전부 예외 대신 typed observation을 반환하는 것과, `_final_answer`가 `missing`과 `mismatched`를 나눠 검사하는 것도 유지한다: 전자는 모델에게 재시도 가능한 지시를, 후자는 위조된 citation identity를 각각 다른 문장으로 돌려준다. `AgentAnswer.model_validate(..., strict=False)`도 유지한다 — 강제 변환이 일어나도 `evidence[chunk_id] != citation` 대조가 원본 identity와 값 단위로 비교하므로 위조 경로가 열리지 않고, `strict=True`로 두면 LLM이 `7`을 `"7"`로 낸 것만으로 근거 있는 답이 버려진다.
  - 정합성 수정 4건: `_strict_json_object`·`_parse_arguments`·`_result`에 한 줄 docstring을 추가했고, 모듈 로컬 `_safe_runtime_error`를 `tools.safe_runtime_error` 호출로 바꿨다(문자열 결과 동일).
- `M9.4`: M2 검색 표면 위의 얇은 built-in filing tool 세 개를 등록하는 코드다(`app/agent/builtin_tools.py`). 각 tool이 payload를 먼저 materialize한 뒤 `finally`에서 `close_read_transaction()`을 호출하는 순서를 유지한다 — 롤백 후에는 ORM 객체가 expire되므로 dict를 만든 다음 트랜잭션을 닫아야 하고, `compare_years`는 `try/finally`가 연도 루프 **안**에 있어야 다음 연도 질의가 앞 연도의 열린 읽기 위에 쌓이지 않는다. `DEFAULT_RRF_K = 60`을 `app/retrieval/hybrid.py`에서 import하지 않고 이 파일에 다시 적은 것도 유지한다: `app.retrieval.hybrid` import는 패키지 `__init__`을 통해 `Settings`를 즉시 생성하고, `EMBEDDING_BATCH_SIZE=0`인 환경에서 `ValidationError`로 실패한다. 이 상수 중복이 `--help`와 패키지 import를 런타임 설정에서 분리하는 장치이며 `tests/agent/test_07_mcp_cli.py`가 그 계약을 고정한다.
  - 정합성 수정 7건: `_hit_payload`, `_search_evidence`, `_compare_evidence`, `_chunk_evidence`와 중첩 헬퍼 `search_filings`·`fetch_chunk`·`compare_years`에 한 줄 docstring을 추가했다.
- `M9.5`: 질의 분해와 그 개선을 측정하는 코드다(`app/agent/decompose.py`, `eval.py`). `decompose_query`가 `result.status != "ok" or result.parsed is None`에서만 원 질문으로 되돌아가는 fallback 범위를 유지한다 — M4 provider는 네트워크 실패를 `provider_error`, 거절을 `provider_refused` 상태로 이미 변환하므로 이 조건이 두 경우를 모두 덮고, 남는 예외(`TypeError`, 시계 역행 `ValueError`)는 호출자 프로그래밍 오류라 삼키면 안 된다. `merge_ranked_lists`가 리스트 내부 중복은 건너뛰고(`seen_in_list`) 리스트 간 identity 충돌은 `ValueError`로 닫는 비대칭도 유지한다: 전자는 한 sub-question이 같은 chunk로 점수를 증폭하는 것을 막고, 후자는 같은 `chunk_id`가 서로 다른 출처를 가리키는 상태를 조용히 융합하지 않는다. `eval.py`는 두 arm이 같은 `moment` 하나를 공유해 per-category paired artifact를 쓰므로 참조 구현과 의도가 같고, `category_metrics`가 `score is None`인 absent case를 빼는 M3 규칙도 그대로다.
  - 정합성 수정 3건: 중첩 헬퍼 `retrieve_decomposed`와 `_arm_payload`·`_artifact_name`에 한 줄 docstring을 추가했다.
- `M9.6`: 같은 registry를 MCP stdio와 acceptance CLI 두 표면으로 노출하는 코드다(`app/agent/mcp_server.py`, `__main__.py`). `call_tool`이 조회·인자 검증 실패에는 `str(error)` 원문을, 실행·직렬화 실패에는 타입명만 남긴 문장을 돌려주는 비대칭을 유지한다 — 앞의 두 실패는 호출자가 보낸 값에 대한 진단이라 원문이 있어야 클라이언트가 호출을 고칠 수 있고, 뒤의 두 실패는 서버 내부 예외라 메시지에 자격증명이 실릴 수 있다. CLI가 `Session`과 `get_embedding_provider`를 함수 본문에서 import하는 것도 유지한다: 이 지연이 `--help`를 DB·설정 로딩과 분리한다.
  - 정합성 수정 2건: 사용처가 없는 `ProviderName = Literal[...]` 별칭과 그 때문에만 남아 있던 `from typing import Literal`을 `__main__.py`에서 제거했다(argparse는 `choices=("deterministic", "openai")` 리터럴을 직접 쓴다). `mcp_server.py`의 두 오류 문장은 `tools.safe_runtime_error` 호출로 바꿨고 결과 문자열은 동일하다.
