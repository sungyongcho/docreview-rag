# M2 실측

이 파일에는 M2의 방향을 결정한 측정 및 출처 검증 근거를 담습니다. 규범 규칙은 [명세](02-spec.md)에, 구현 순서는 [빌드 가이드](03-build.md)에 있습니다.

## F1 — Python 3.14 환경에는 로컬 임베딩 모델이 필요하지 않음

이 프로젝트는 Python 3.14.1 환경에서 실행되며 OpenAI 2.53.0, SQLAlchemy 2.0.51, asyncpg, pgvector가 이미 포함되어 있습니다. 로컬 Sentence Transformers 의존성을 추가하면 M2에 필요하지 않은 별도의 PyTorch 호환성 및 메모리 경계가 생깁니다.

결정: 비동기 `EmbeddingProvider` 경계를 유지합니다. 구성된 프로덕션 공급자로 OpenAI를 사용하고, 테스트와 오프라인 실습에는 별도 의존성이 없는 결정론적 토큰 해시 공급자를 사용합니다.

근거: 공급자 테스트는 네트워크에 접근하지 않고 실행되며, 실제로 구성한 OpenAI 프로브는 유한한 값으로 이루어진 384차원 벡터 하나를 반환했습니다.

## F2 — OpenAI는 명시적으로 축소한 임베딩 차원을 지원함

설치된 비동기 SDK는 `dimensions`와 `encoding_format`을 `embeddings.create`에서 받습니다. 현재 OpenAI 문서에는 `text-embedding-3-small`이 임베딩 모델로 명시되어 있으며, 공식 SDK는 `dimensions` 매개변수를 `text-embedding-3` 모델에 대해 선언합니다.

결정: 384 개의 float 구성 요소를 명시적으로 요청하고, 누락되거나 중복되거나 순서가 바뀌었거나 유한하지 않거나 형태가 잘못된 응답은 PostgreSQL에 도달하기 전에 거부합니다.

주요 참고 자료:

- [OpenAI text-embedding-3-small](https://developers.openai.com/api/docs/models/text-embedding-3-small)
- [OpenAI Python 임베딩 리소스](https://github.com/openai/openai-python/blob/main/src/openai/resources/embeddings.py)

## F3 — 측정 전 기준선으로는 정확한 pgvector 검색이 적합함

pgvector는 기본적으로 정확한 최근접 이웃 검색을 수행합니다. 근사 인덱스는 재현율과 속도를 맞바꾸며 결과를 바꿀 수 있습니다. M2의 청크는 9,172 개뿐이고, 검색 품질과 지연 시간 측정은 M3가 담당합니다.

결정: `<=>`를 사용해 코사인 거리순으로 정렬하고, `ChunkHit`을 만들 때만 거리를 유사도로 변환하며, M3 측정 전에는 HNSW 또는 IVFFlat 인덱스를 생성하지 않습니다.

주요 참고 자료: [pgvector 쿼리 및 인덱싱](https://github.com/pgvector/pgvector#querying).

## F4 — PostgreSQL FTS는 어휘 기준선이며 문자 그대로의 BM25가 아님

PostgreSQL은 `websearch_to_tsquery`를 통한 유연한 웹 검색 쿼리 구문 분석과 `ts_rank_cd`를 통한 범위 밀도 순위화를 제공합니다. PostgreSQL의 고유 순위화 방식은 BM25 공식이 아닙니다.

결정: 원시 쿼리 값을 바인딩하고, 생성된 `content_tsv`를 사용하며, `ts_rank_cd`로 순위를 매기고, 결과를 PostgreSQL 전문 검색이라고 정확하게 설명합니다.

주요 참고 자료: [PostgreSQL 텍스트 검색 제어](https://www.postgresql.org/docs/current/textsearch-controls.html).

## F5 — 고유 점수는 안전하게 융합할 수 없음

코사인 유사도와 `ts_rank_cd`는 서로 다른 양을 측정하며 척도도 다릅니다. 가중합을 사용하면 문서화되지 않은 보정 방식을 선택하게 되고, 말뭉치나 쿼리 형식이 바뀔 때 불안정해집니다.

결정: RRF로 1부터 시작하는 순위를 융합하고, 구성 요소의 출처 정보는 정렬된 청크 ID로만 공개합니다. 공개 구성 요소 구조에는 점수 필드가 없습니다.

회귀 테스트: `test_service_uses_one_session_sequentially_and_exposes_rank_only_components`.

## F6 — 하나의 `AsyncSession`을 사용하려면 순차적으로 구성해야 함

SQLAlchemy 비동기 세션은 변경 가능한 트랜잭션 상태를 나타내므로 여러 태스크에서 동시에 사용하기에 안전하지 않습니다. 구성 요소마다 세션을 만들면 트랜잭션과 연결의 소유권도 불분명해집니다.

결정: 서비스 내부의 벡터 및 어휘 어댑터는 호출자가 제공한 하나의 세션을 캡처합니다. `hybrid_search`는 벡터 어댑터를 먼저 기다린 다음 어휘 어댑터를 기다립니다.

회귀 테스트: 서비스 테스트는 `embed`, `vector`, `lexical` 이벤트를 기록하고 두 데이터베이스 호출이 같은 객체를 받는지 확인합니다.

## F7 — 문자 그대로 사용한 인수 쿼리에서 약어 불일치가 드러남

실제 말뭉치를 처음 실행할 때 사용한 쿼리는 `"NVDA 2024 R&D"`였습니다. PostgreSQL은 마지막 약어를 `'r' & 'd'`로 구문 분석했으므로 어휘 구성 요소가 아무 행도 반환하지 않았습니다. 결정론적 공급자도 `r`과 `d`를 해시했지만, 공시 문구에는 `Research and Development`로 풀어 쓰는 경우가 많습니다. 그 결과 요청한 공시보다 Intel 청크가 잘못 높은 순위를 차지했습니다.

결정: 프로덕션 서비스는 일반적인 `R&D` 약어를 `research development`로 확장한 뒤 쿼리 임베딩과 어휘 검색 모두에 전달합니다. CLI에는 사용자의 원래 쿼리를 그대로 표시합니다.

회귀 테스트: 서비스 테스트는 두 구성 요소가 모두 `"NVDA 2024 research development"`를 받는지 확인하며, 실제 인수 경로에서는 NVDA FY2024 청크가 1위를 차지합니다.

## F8 — SQLAlchemy가 벡터 열을 만들기 전에 pgvector가 있어야 함

새 PostgreSQL 데이터베이스는 확장을 활성화하기 전까지 `vector(384)` 타입을 알지 못합니다. 따라서 `Base.metadata.create_all`을 먼저 호출하면 청크 테이블을 생성하기 전에 실패합니다.

결정: 하나의 멱등 부트스트랩 트랜잭션에서 `CREATE EXTENSION IF NOT EXISTS vector`를 실행한 뒤 `create_all`을 호출합니다. 기존 시드 CLI는 `--create-schema`가 명시된 경우 이 도우미를 사용합니다.

회귀 테스트: 단위 테스트는 작업 순서를 기록하며, 실제 테스트는 임시 벡터 테이블을 사용하기 전에 확장을 두 번 활성화합니다.

## F9 — 결과 제한은 유용한 융합 후보 제한이 아님

벡터와 어휘 후보를 `k`개만 요청하면 두 구성 요소 모두에서 중간 정도의 순위를 차지한 청크를 RRF가 복구할 여지가 거의 없습니다. 따라서 프로덕션 서비스는 `max(20, 4 * k)`를 사용하되, `candidate_k`를 명시한 경우에는 `k` 이상인 값을 그대로 유지합니다.

회귀 테스트: 서비스 테스트는 `candidate_k`를 생략하고, 순차적으로 이루어지는 두 구성 요소 호출 모두 `k=2`일 때 20 값을, `k=6`일 때 24 값을 받는지 검증합니다.

## F10 — 하나의 루프백 이벤트 루프로 실제 테스트를 제한함

기존 실제 테스트는 `localhost`를 해석하고, 연결 가능 여부 확인과 테스트 실행에 각각 `asyncio.run`을 호출했습니다. 그러면 Python 3.14 샌드박스에서 SQL 작업이 이미 끝난 뒤에도 실행기 종료가 300초 동안 대기할 수 있었습니다.

결정: 세션 범위 테스트 픽스처는 루프백 데이터베이스 URL만 허용하고, 호스트를 `127.0.0.1`로 정규화하며, 하나의 이벤트 루프에서 연결 프로브와 임시 테이블 인수 테스트를 실행합니다.

## F11 — 기록된 검증 근거

2026-08-12 날짜에 PostgreSQL 16.14 및 pgvector 0.8.3 버전을 대상으로 기록했습니다.

| 검사 | 정확한 결과 |
|---|---|
| 검색 단위/통합 테스트 모음 | 90개 통과, 0개 건너뜀, 0개 실패 |
| 계층별 개수 | 누적 테스트 29, 41, 52, 61, 70, 79, 88, 90개 |
| 시드 부트스트랩 | 문서 20개와 청크 9,172개 커밋 |
| 결정론적 백필 | 9,172개 선택, 9,172개 임베딩, 0개 오래된 항목, 72개 배치 |
| 결정론적 인수 테스트 | 최상위 검색 결과는 청크 9056, `NVDA-FY2024`, 항목 15, 테이블 |
| 인수 테스트 구성 요소 순위 | 벡터 청크 ID 20개, 어휘 청크 ID 13개, 구성 요소 점수 없음 |
| 실제 OpenAI 공급자 프로브 | 구성 요소 384개, 모두 유한함, 유클리드 노름 0.999817907 |
| 근사 인덱스 | `chunks`에 HNSW 인덱스 0개 |

PostgreSQL 테스트는 연결 범위 임시 테이블을 사용했고 건너뛰지 않고 통과했습니다. 그런 다음 실제 말뭉치 인수 명령은 멱등 시드 부트스트랩을 통해 채운 애플리케이션 스키마를 사용했습니다. 같은 애플리케이션 데이터베이스에 이미 결정론적 벡터가 들어 있었으므로 실제 OpenAI 말뭉치 백필은 수행하지 않았습니다. 공급자 공간을 혼합하면 검색 결과가 유효하지 않기 때문입니다.
