# M5 버그

## B1 — FastAPI 테스트는 통과했지만 TestClient 사용 중단 경고가 발생했다

- **증상:** 초기 런타임 테스트 14 건이 통과했지만 Starlette가 `httpx2`를 권장하는 경고를 표시했습니다.
- **근본 원인:** 제약 없는 의존성 해석이 Starlette 1.6.0 버전을 선택했으며, 이 버전에서는 일반 HTTPX 호환 경로가 이미 사용 중단 상태였습니다.
- **수정:** `starlette<1`로 제한합니다. 잠금 파일은 Starlette 0.52.1 버전을 FastAPI 0.141.1 및 HTTPX 0.28.1 버전과 함께 선택합니다.
- **회귀 방지:** 집중 API 테스트는 TestClient 경고 없이 실행되어야 합니다.

## B2 — 모듈 애플리케이션에는 라우트가 있었지만 프로덕션 서비스가 없었다

- **증상:** `/health`와 OpenAPI는 동작했지만 모든 도메인 리소스가 `service_unavailable`을 반환했고, 테스트가 `FakeApiServices`를 주입한 경우에만 달랐습니다.
- **근본 원인:** `create_app()`이 실제 `ApiServices` 구현을 설치하지 않은 채 M5.1 팩토리에 위임했습니다.
- **수정:** 기본적으로 `RuntimeApiServices`를 생성하고 테스트를 위한 명시적 주입을 유지합니다.
- **회귀 방지:** M5.3 단계는 런타임 어댑터를 통해 실제 M2/M4 호출 연결 지점을 관찰합니다.

## B3 — CLI가 검색 내부 필드를 누출했다

- **증상:** HTTP는 `EvidenceHit`를 반환했지만 CLI는 전체 `ChunkHit`를 직렬화하면서 `index_text`를 포함했습니다.
- **근본 원인:** 두 출력 경로가 서로 다른 Pydantic 직렬화기를 독립적으로 호출했습니다.
- **수정:** 두 인터페이스 모두 `EvidenceHit.from_chunk_hit()`를 사용합니다.
- **회귀 방지:** 전체 공개 객체를 비교하고 `index_text`가 없음을 단언합니다.

## B4 — 임포트 시 안전한 상태 확인과 데이터베이스 준비 상태를 혼동했다

- **증상:** 상태 확인에서 `SELECT 1`을 수행하면 ASGI와 오류 처리가 동작하는데도 데이터베이스 시작 또는 유지보수 중 애플리케이션이 비정상으로 표시됩니다.
- **근본 원인:** 하나의 엔드포인트가 프로세스 활성 상태와 의존성 준비 상태를 모두 판단하려고 했습니다.
- **수정:** `/health`는 활성 상태만 확인하며 도메인 호출은 타입이 지정된 의존성 실패를 반환합니다. Compose는 별도로 데이터베이스가 정상 상태가 될 때까지 기다립니다.
- **회귀 방지:** 데이터베이스가 없어도 상태 확인은 통과하고, 구성되지 않은 리뷰는 타입이 지정된 `503`을 반환합니다.

## B5 — 환경 자격 증명이 우발적인 권한으로 바뀔 수 있었다

- **증상:** 단순한 기본 OpenAI 공급자를 사용하면 셸이나 컨테이너가 키를 상속할 때마다 `/review`가 실시간 호출을 수행하게 됩니다.
- **근본 원인:** 구성의 가용성을 사람의 동의와 예산 승인으로 간주했습니다.
- **수정:** 주입된 LLM 공급자와 주입된 공급자 예산을 함께 요구합니다.
- **회귀 방지:** 기본 런타임은 공급자 요청 없이 리뷰를 거부합니다.

## B6 — 프로젝트를 설치하지 않는 환경에서는 설치된 콘솔 스크립트를 사용할 수 없었다

- **증상:** 의존성만 동기화한 뒤 `uv run docreview --help`를 실행할 수 없었습니다.
- **근본 원인:** 이 소스 트리 프로젝트는 컨테이너 계층에서 의도적으로 패키지로 설치되지 않습니다.
- **수정:** 어디서나 결정론적 모듈 진입점 `uv run python -m app.cli`을 사용합니다.
- **회귀 방지:** 하위 프로세스 테스트는 `python -m app.cli --help`를 실행하고 세 명령을 모두 검사합니다.
