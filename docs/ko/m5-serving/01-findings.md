# M5 실측

이 결과는 2026-08-12 기준 오프라인 인수 환경을 설명합니다. 유료 또는 실시간 공급자 요청은 실행하지 않았습니다.

## F1 — HTTP 경계는 도메인 내부를 직렬화하지 말고 근거를 투영해야 한다

M2 `ChunkHit`에는 검색에 문맥과 근거가 모두 필요하므로 `index_text`가 포함됩니다. 공개 HTTP 근거 리소스는 본문, 문맥 헤더, 점수, 인용, 청크 ID, 소스 구간, 소스 해시를 의도적으로 노출하지만, 중복되는 내부 인덱스 문자열은 노출하지 않습니다.

결정: `EvidenceHit.from_chunk_hit()`가 공개 투영을 소유합니다. CLI도 같은 투영을 사용하므로 CLI와 HTTP가 서로 다른 근거 계약으로 어긋날 수 없습니다.

회귀 방지: `test_cli_and_http_use_the_same_public_evidence_shape`는 전체 객체를 비교하고 `index_text`가 없음을 검증합니다.

## F2 — 라우터만으로는 프로덕션 구성이 완성되지 않는다

첫 번째 API 구현 경로는 의존성 주입을 올바르게 사용했지만, 모듈 수준 애플리케이션에는 데이터베이스 기반 서비스가 없었습니다. 따라서 모든 도메인 라우트가 타입이 지정된 `503`을 반환했고, 가짜 서비스를 주입한 테스트만 성공할 수 있었습니다.

결정: `RuntimeApiServices`는 요청이 소유하는 `AsyncSession` 위에서 같은 프로토콜을 구현합니다. 공급자가 명시적으로 주입되지 않으면 검색은 결정론적 임베딩으로 M2에 위임하고, 리뷰는 M4에 위임한 뒤 결과 실행을 영속화하며, 조회는 데이터베이스 행을 다시 엄격한 API 리소스로 매핑합니다.

회귀 방지: M5.3 통합 테스트는 직접 호출과 M4 내부 호출 양쪽의 M2 검색 호출, 주입된 공급자, 요청당 하나의 세션, 실행 영속화를 관찰합니다.

## F3 — 리뷰는 환경 자격 증명에서 유료 호출 권한을 추론해서는 안 된다

애플리케이션 프로세스는 관련 없는 명령을 위해 `OPENAI_API_KEY`를 상속할 수 있습니다. 키의 존재를 권한으로 간주하면 `/review`가 예기치 않게 비용을 지출할 수 있습니다.

결정: 프로덕션 리뷰에는 주입된 `LLMProvider`와 주입된 `ProviderBudget`이 모두 필요합니다. 기본 런타임은 타입이 지정된 `provider_unavailable` `503`을 반환하지만, 상태 확인, OpenAPI, 검색, 문서, 수집, 실행, 트레이스, 평가는 계속 연결되어 있습니다.

회귀 방지: `test_default_runtime_is_live_but_review_is_fail_closed_without_provider`는 같은 프로세스에서 활성 상태와 요청 거부를 함께 검증합니다.

## F4 — 활성 상태와 의존성 준비 상태는 서로 다른 문제다

컨테이너에는 코퍼스가 채워지기 전에도, 공급자를 호출하지 않고도 성공할 수 있는 상태 점검이 필요합니다. `/health`에서 데이터베이스를 조회하면 프로세스 활성 상태와 애플리케이션 준비 상태가 뒤섞여 데이터베이스 유지보수 중 재시작 루프가 발생합니다.

결정: `/health`는 ASGI 프로세스가 HTTP에 응답할 수 있음을 검증합니다. 의존성이 준비되지 않으면 도메인 엔드포인트는 타입이 지정된 `database_unavailable` 또는 `provider_unavailable` 실패를 노출합니다. Compose는 별도로 PostgreSQL이 정상 상태가 될 때까지 기다린 뒤 애플리케이션을 시작합니다.

## F5 — 호환되는 TestClient 스택에는 명시적인 Starlette 상한이 필요했다

초기 의존성 해석에서는 FastAPI 0.141.1, Starlette 1.6.0, HTTPX 0.28.1 버전이 선택되었습니다. 테스트는 통과했지만 Starlette는 일반 HTTPX TestClient 지원이 `httpx2`를 위해 사용 중단되었다고 경고했습니다.

결정: FastAPI 0.141.1 버전과 HTTPX 0.28.1 버전을 유지하면서 `starlette<1`로 고정합니다. 잠금 파일은 FastAPI가 선언한 호환 범위 안의 Starlette 0.52.1 버전을 경고 없이 선택합니다.

## F6 — 오프라인 인수는 완료되었으며 로컬 DB 기반 검색 curl은 조건부다

측정된 검증 결과는 `40 passed`로, `tests/api`에서 얻었습니다. 전체 스위트 결과는 `691 passed, 1 skipped`였습니다. Ruff, 소유 파일 포맷 검사, Compose 파싱, 애플리케이션 이미지 빌드, 문서 동기화, 로컬 Uvicorn 상태 확인/OpenAPI curl 스모크 테스트가 모두 통과했습니다.

데이터베이스 기반 `/retrieve` 스모크 테스트에는 실행 중이고 스키마가 최신이며 데이터가 채워진 로컬 PostgreSQL 코퍼스가 필요합니다. 이는 별도의 실시간 로컬 게이트로 문서화되어 있으며, 공급자 또는 네트워크 인수 테스트로 보고해서는 안 됩니다.
