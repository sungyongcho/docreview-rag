# M1.3 개요 — 구조 기반 청킹과 소스 안정적 인용

> **`zero` 브랜치 참고:** 아래 완성 코드는 고정된 참조 목표이며 정식 파일은 직접 작성한다. 진행 상태: [모듈 플랜](../../project/module-plan.md).

> 입력: M1.1 `ParsedFiling` + M1.2 표 마크다운 변환기 출력: 검색 및 저장 가능한 `Chunk` 목록 핵심: 청크 ID가 아니라 고정 원문 `[start_char, end_char)`와 `source_sha256`가 인용 좌표다.

## 한 문장

**Section/Block 구조를 지키며 텍스트와 표를 검색 단위로 만들고, 합성 검색 문맥과 원문 본문을 분리하여 모든 결과가 정확한 10-K 원문 스냅샷으로 돌아가게 한다.**

## 파이프라인

1. 파서가 소스 스냅샷의 길이와 SHA-256, 각 Block의 반개방 구간을 만든다. 2. 텍스트는 Item, 서술형 제목, 연속 소스 그룹, 표 경계를 넘지 않고 문단 단위로 묶는다. 3. 표는 행 수준 출처 추적 정보가 없으므로 원본 표 하나를 정확히 하나의 표 청크로 만든다. 4. 공시, Item, 제목은 `context_header`에만 넣고 원문 기반 `body`와 분리한다. 5. 원문 구간 순서로 정렬한 뒤 빈틈없는 ordinal을 부여한다. 6. M1.4는 `body`, `context_header`, `index_text`를 각각 출처 추적과 인덱싱 용도로 저장하고 `content`는 `index_text`의 ORM 별칭으로만 제공한다.

## 책임 경계

- M1.1: Item, Block, 소스 스냅샷과 좌표를 만든다.
- M1.2: 소스 표 HTML을 마크다운 본문으로 바꾼다.
- M1.3: 검색 단위, 검색 문맥, 인용 구간을 만든다.
- M1.4: 문서와 청크를 PostgreSQL에 재실행 가능하게 저장한다.
- M3: 청크 목표와 검색 품질을 어블레이션 실험으로 결정한다.

M1.3의 완료 기준은 특정 청크 크기가 아니라 **설정을 바꿔도 소스 인용이 유지되는 구조**다.
