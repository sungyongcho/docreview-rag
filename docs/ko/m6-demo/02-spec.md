# M6 명세

이 문서는 M6의 규범적 기준입니다. 포트폴리오에서 주장할 수 있는 내용, 데모가 노출해야 하는 항목, M6.3 완료 시 결합할 증거를 정의합니다.

## 1. 의존성과 순서

- M6.1 단계와 M6.2 단계에는 각각 M5.3 항목이 필요합니다.
- M6.1 단계와 M6.2 단계는 병렬로 진행할 수 있습니다.
- M6.3 단계에는 M6.1 단계와 M6.2 단계가 모두 필요합니다.
- 문서에 표시되는 순서는 `M6.1 -> M6.2 -> M6.3`으로 유지해야 합니다.

## 2. 포트폴리오 독자

주 독자는 저장소가 증거 기반 시스템 설계를 보여 주는지 빠르게 판단해야 하는 엔지니어나 검토자입니다. 랜딩 페이지는 다음 질문에 답해야 합니다.

1. 시스템은 어떤 문제를 해결합니까? 2. 어떤 경계가 결정론적이며 검증되었습니까? 3. 평가에서 무엇을 측정했습니까? 4. 무엇이 실패했거나 아직 입증되지 않았습니까? 5. 어떤 정확한 명령어로 로컬 증거를 재현할 수 있습니까?

## 3. 공개 증거 카드

지원되는 모든 데모 결과는 직접 또는 렌더링된 증거 JSON을 통해 다음을 노출해야 합니다.

- 사람이 읽을 수 있는 인용
- 반개방 원문 범위
- 소스 SHA-256
- 양의 청크 ID
- 증거 본문

지원되지 않는 결과는 빈 증거 모음을 노출해야 합니다. 프레젠테이션 코드가 자리표시자 인용을 만들어서는 안 됩니다.

## 4. 추적 및 비용 표면

데모에서는 모드, 상태, 모델/공급자 표기, 요청 수, 입력 토큰, 출력 토큰, 예상 비용, 지연 시간을 보여야 합니다. 타입이 지정된 실패에는 정제된 오류 메시지를 추가할 수 있습니다. 자격 증명 이름과 값, 인증 헤더, 임의 예외 표현을 렌더링해서는 안 됩니다.

## 5. 데모 모드와 표기

| 모드 | 필수 표기 | 허용되는 주장 |
|---|---|---|
| 미리 준비됨 | `canned fixture` | 결정론적인 지원/미지원 UI 동작, 공급자 비용 없음 |
| 런타임 쿼리 | `local runtime retrieval` | 주입된 M5 검색을 통해 반환된 증거 |
| 런타임 검토 | `local runtime review` | 주입된 M5 워크플로와 추적 계약을 통한 보호된 검토 |

현재 명령어는 미리 준비된 모드를 실행합니다. 주입형 런타임 서비스 어댑터는 실제 M5 반환 타입에 대해 검증되지만, 런타임 표기는 기록하는 실행에 해당 서비스를 명시적으로 주입한 경우에만 사용할 수 있습니다.

## 6. 평가 주장 규칙

- 최고 지표만이 아니라 청크 구성/전략 실험군 6개를 모두 보고하십시오.
- 지표는 긍정 사례 24 건을 채점하지만 아티팩트에는 질문 28 개가 모두 들어 있다고 명시하십시오.
- 골든 사례는 에이전트가 선별했으며 작성자 승인을 기다리고 있다고 명시하십시오.
- 결정론적 토큰 해시 벡터가 의미론적 공급자의 품질을 나타내지 않는다고 명시하십시오.
- 기록된 낮고 엇갈린 지표를 근거로 프로덕션 구성을 선택하지 마십시오.
- 유료 공급자의 예상치와 실행을 결정론적 인수 과정과 분리하십시오.

## 7. 스크린샷 정책

누락된 스크린샷은 `placeholder`라는 단어와 증거가 아니라는 명시적 설명이 담긴 텍스트로만 나타낼 수 있습니다. 스크린샷은 선택 사항이며, 커밋할 경우 다음 항목을 포함하거나 함께 제공해야 합니다.

- 테스트한 커밋/리비전
- 데모 모드 표기
- 쿼리와 화면에 보이는 증거 정체성
- 인수 명령어 결과
- 비밀이 보이지 않는다는 확인

조작된 프레임, 모의 결과 또는 표기 없는 미리 준비된 캡처를 현재 런타임 동작으로 제시해서는 안 됩니다.

## 8. 명령어와 언어

설정, 테스트, 실행, curl, 재현 명령어는 저장소 루트에서 바로 복사해 실행할 수 있어야 합니다. 모든 코드 블록, 셸 명령어, 코드 주석, 독스트링은 영어로 작성해야 합니다. 한국어 설명문은 허용됩니다.

## 9. 문서 세트

M6에는 `00-README.md`부터 `05-verify.md`까지와 포트폴리오용 아키텍처, 평가, 실패 보고서가 포함되어야 합니다. 루트 README, `docs/00-README.md`, `docs/project/module-plan.md`는 규범적 구현 세부 내용을 중복하지 않으면서 표준 M6 경로로 연결되어야 합니다.

## 10. 인수

문서 링크/소스 블록이 동기화되고, 정확한 명령어가 유효하며, 측정된 주장이 저장소 아티팩트나 테스트로 추적되고, 스크린샷이 정직하게 표기되면 M6.2 항목이 완료됩니다.

M6.3 단계에서 실제 M5/M6 반환 타입 통합을 입증하고, 전체 스위트를 다시 실행하고, 측정된 통과/건너뜀 수를 게시하고, 부재한 모든 스크린샷을 증거가 아닌 자리표시자로 정직하게 표시하면 M6가 완료됩니다.
