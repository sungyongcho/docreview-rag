# M6 개요 — 포트폴리오 표면

> **`zero` 브랜치 참고:** 아래 완성 코드는 고정된 참조 목표이며 정식 파일은 직접 작성한다. 진행 상태: [모듈 플랜](../../project/module-plan.md).

M6에서는 작동하는 문서 검토 시스템을 정직하고 재현 가능한 포트폴리오 표면으로 전환합니다. 사용자에게 보이는 경로는 **M6.1 Gradio 데모 -> M6.2 포트폴리오 문서 -> M6.3 통합**입니다. M6.1 단계와 M6.2 단계는 M5.3 항목을 공통 선행 조건으로 삼으며 병렬로 구축할 수 있고, M6.3 단계에서 두 경로를 합칩니다.

## 현재 마일스톤 상태

| 단계 | 결과 | 측정된 상태 |
|---|---|---|
| M6.1 | Gradio 증거 데모 | 완료: 테스트 6건 통과, UI 빌드와 `127.0.0.1:7861` 루프백 시작/종료 성공 |
| M6.2 | 포트폴리오 설명과 보고서 | 완료: 아키텍처, 평가, 실패, 튜토리얼, 명령어, 인덱스 동기화 |
| M6.3 | 런타임/데모 통합 및 최종 회귀 | 완료: 실제 `RetrievalResult.hits` 회귀, 저장소 게이트, `697 passed, 1 skipped` |

M6 이후 체크포인트는 전체 스위트를 실행해 측정한 `697 passed, 1 skipped`이며, 이전 결과인 `691 passed, 1 skipped`에 산술적으로 더한 값이 아닙니다. M6는 완료되었고, 다음 단계는 배포 준비가 된 릴리스를 만드는 M7입니다.

## 마일스톤 계약

`measured repository behavior -> explicit tradeoffs -> reproducible commands -> honest demo`

포트폴리오에서는 다음 네 가지 상태를 구분할 수 있어야 합니다.

1. 인용, 원문 범위, 해시, 청크 ID를 갖춘 근거 있는 증거 2. 제공된 문서에서 찾지 못한 사실과, 조작된 증거가 없는 상태 3. 비밀을 노출하지 않는 추적, 요청, 토큰, 비용, 지연 시간 정보 4. 그럴듯하게 꾸민 대체 답변 대신 타입이 지정된 서비스 또는 예산 실패

기본 Gradio 서비스는 합성 Acme 픽스처를 사용합니다. 이는 UI 동작과 비용 없는 실행을 입증할 뿐, 커밋된 AMD, INTC, MU, NVDA 말뭉치를 대상으로 한 검색을 입증하지는 않습니다. 주입형 런타임 어댑터는 별도로 실제 M5 `RetrievalResult.hits` 계약에 대해 검증됩니다.

## 가장 빠르고 정직한 데모

```bash
uv sync --locked --extra demo
uv run --extra demo python -m app.demo
```

Gradio가 출력한 URL을 엽니다. 결과에는 **canned fixture**라고 표시하십시오. 이를 실제 SEC 검색이나 모델 기반 답변이라고 표현해서는 안 됩니다.

## 스크린샷 상태

> **자리표시자 — 스크린샷도 증거도 아닙니다.** 커밋된 이미지는 없습니다. 향후 캡처에는 `canned fixture` 또는 로컬 런타임 모드를 명시하고 스크린샷 릴리스 게이트를 통과해야 합니다. 이 자리표시자에는 증거로서의 가치가 없습니다.
