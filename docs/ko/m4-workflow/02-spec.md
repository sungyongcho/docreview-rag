# M4 명세

## 1. 범위

M4는 M2 `ChunkHit` 값을 받아 M4.2 `RunReport`를 반환합니다. 데이터베이스 트랜잭션, HTTP 라우트, UI 상태, 공급자 자격 증명은 소유하지 않습니다. 이러한 경계는 호출자에게 남아 있습니다.

워크플로에는 이름이 지정된 네 개의 노드가 있습니다.

```text
retrieve -> grade -> check -> report
```

`grade`와 `check`만 LLM 경계입니다. `retrieve`는 주입된 M2 검색기를 호출하고, `report`는 결정론적 투영입니다.

## 2. 엄격한 요청 및 상태

`WorkflowRequest`에는 안정적인 실행 ID, 비어 있지 않은 쿼리, 양수 `k`, 정확한 검색 필터, 워크플로 예산, 공급자 예산, 음수가 아닌 컨텍스트 문자 제한, 완전한 시스템 프롬프트가 필요합니다. 알 수 없는 필드와 스칼라 강제 변환은 거부됩니다.

`WorkflowState`는 동결되어 있습니다. 전이는 적중 항목, 증거, 관련 청크 ID, 사유, 노드 경로, 추적을 불변 튜플로 담은 새 값을 반환합니다. 순수 노드는 I/O 작업을 수행하거나, 환경 변수를 읽거나, 시간을 호출하거나, 입력 상태를 변경하지 않습니다.

## 3. 타입이 지정된 성능 저하 사유

정상 경로가 아닌 모든 경로는 다음 판별 값 중 하나를 사용합니다.

| 코드 | 의미 |
|---|---|
| `retrieval_empty` | 반환된 청크가 없음 |
| `duplicate_retrieved_chunks` | 중복된 청크 식별자가 제거됨 |
| `duplicate_evidence_text` | 같은 본문을 담은 서로 다른 청크 식별자가 하나로 합쳐짐 |
| `document_quota_applied` | 한 문서의 몫을 넘어선 적중 항목이 제외됨 |
| `context_truncated` | 완전한 청크가 컨텍스트 제한을 초과함 |
| `grade_references_filtered` | 평가기가 알 수 없는 청크를 지정함 |
| `grade_coverage_incomplete` | 평가기가 제공된 청크를 누락함 |
| `relevance_below_threshold` | 관련 있음으로 평가된 유효한 청크가 없음 |
| `citations_filtered` | 검사기가 관련 집합에 속하지 않는 증거를 인용함 |
| `supported_without_citations` | 지원되는 답변에서 유효한 인용이 모두 사라짐 |
| `provider_failure` | 타입이 지정된 공급자 거부로 평가 또는 검사가 중단됨 |
| `node_error` | 공급자 이외의 의존성이 타입이 지정된 데이터를 반환하기 전에 예외를 발생시킴 |

사유는 최종 보고서 또는 최종 실패 객체로 직렬화됩니다. 아무런 표시 없이 버리는 것은 허용되지 않습니다.

## 4. 검색 계약

주입된 검색기는 `(query, k, filters)`를 받아 `RetrievalResult` 또는 `ChunkHit` 시퀀스를 반환합니다. 결과는 검색 순서를 유지합니다. 워크플로는 최종적으로 남길 `evidence_overfetch` 배수만큼 `k`보다 많은 적중 항목을 요청합니다. 아래의 모든 선별 단계는 적중 항목을 제거하기만 하는 반면, 검색은 요청받은 개수까지만 남기기 때문입니다.

이어서 선별이 그 목록을 네 단계로 순서대로 좁힙니다. 중복된 청크 ID는 첫 번째 적중 항목을 유지하고 제거된 식별자를 기록합니다. 공백을 정규화한 `body`가 일치하는 서로 다른 청크 ID도 첫 번째 적중 항목을 유지하고, 어느 식별자가 어느 식별자를 흡수했는지 기록합니다. 하나의 `doc_id`는 최대 `max_hits_per_document`개까지만 기여합니다. 살아남은 항목은 `k`개로 잘립니다.

컨텍스트 선택은 완전한 `index_text` 값과 구분자를 합산합니다. 전체 값이 제한 안에 들어갈 때만 청크를 포함합니다. 제외된 청크는 출처 확인을 위해 `retrieved_hits`에 남지만 `evidence`에는 없으며 평가하거나 인용할 수 없습니다.

유효한 증거가 0개이면 곧바로 보고 단계로 이동하여 `NOT_IN_DOCS`를 반환합니다.

## 5. 평가 계약

평가 프롬프트에는 쿼리와 결정론적 JSON 증거가 들어갑니다. 증거는 신뢰할 수 없는 데이터로 표시됩니다. 공급자는 제공된 각 청크마다 고유한 `ChunkRelevance` 하나를 반환해야 합니다.

알 수 없는 평가 ID는 제거하고, 누락된 ID는 관련 없음으로 처리하며, 두 경우 모두 기록합니다. 최소 관련 항목 수는 1개입니다. 이에 미달하면 곧바로 보고 단계로 이동하며 검사 단계는 호출하지 않습니다.

## 6. 검사 및 인용 계약

검사 프롬프트에는 평가 단계를 통과한 청크만 들어갑니다. `AnswerDecision`은 먼저 레이블 형태를 강제합니다. 지원되는 결정에는 구문상 유효한 인용이 하나 이상 필요하지만, `NOT_IN_DOCS`는 인용을 금지하고 정확한 부재 답변을 요구합니다.

그런 다음 워크플로 코드가 의미론적 인용 소속 여부를 강제합니다.

1. 요청된 ID와 평가된 증거 ID의 교집합을 구합니다. 2. 제거된 모든 ID를 기록합니다. 3. 유효한 ID를 모델이 반환한 순서대로 유지합니다. 4. 유효한 ID가 남지 않으면 `SUPPORTED`를 `NOT_IN_DOCS`로 낮춥니다.

최종 보고서는 모델 텍스트가 아니라 저장된 `ChunkHit` 값에서 인용 메타데이터를 구성합니다.

## 7. 공급자 실패 계약

M4.1 단계는 엄격한 검증, 한 번의 복구, 타입이 지정된 거부를 수행합니다. M4.3 단계는 상태를 다음과 같이 매핑합니다.

| 공급자 상태 | 실행 상태 |
|---|---|
| `schema_rejected` | `schema_rejected` |
| `budget_exceeded` | `budget_exceeded` |
| `provider_refused` | `error` |
| `provider_error` | `error` |

공급자 메타데이터는 최종 원시 출력, 토큰 합계, 지연 시간, 재시도 횟수, 모델, API URL을 포함해 항상 `StepTrace`가 됩니다. 실패하면 즉시 중단하며 가짜 답변 보고서를 만들지 않습니다.

## 8. 누적 예산 계약

단일 강제 함수는 `pre_node_budget_guard`입니다. 러너는 누적된 `node_path`와 `steps`를 사용해 모든 노드 직전에 이 함수를 호출합니다. 반복 횟수, 입력 토큰, 출력 토큰, 경과 시간을 이 안정적인 순서로 검사합니다.

한도와 같으면 진입을 거부합니다. 값이 영인 제한은 유효하며 첫 노드를 결정론적으로 차단합니다. 음수, 유한하지 않은 값, 불리언 또는 강제 변환된 제한은 스키마 오류입니다.

공급자 호출 예산에서는 이전 워크플로 사용량을 차감합니다. 따라서 공급자 경계는 남은 허용량을 초과한 응답에 대해 타입이 지정된 초과 결과를 반환할 수 있으며, 다음 노드 실행 전 검사는 성공한 이전 호출로 소진된 용량을 포착합니다.

## 9. 영속성 계약

러너는 `RunReport`를 반환하며 트랜잭션을 커밋하지 않습니다. 호출자는 이 값을 `report_to_records` 또는 `persist_run_report`에 전달합니다. 시스템 프롬프트, 원시 출력, 노드 경로, 카운터, 구조화 답변, 타입이 지정된 실패는 그대로 유지되며, 식별 가능한 값과 호출자가 제공한 비밀 값은 영속성 경계에서만 가려집니다.

## 10. 프레임워크 호환성

잠긴 환경에는 LangGraph 의존성이 없습니다. R1 구현은 동등한 타입 기반 비동기 러너를 사용합니다. 순서 제어는 의도적으로 얇으며, 필요성이 측정된 뒤 LangGraph를 도입한다면 순수 노드 함수가 호환되는 마이그레이션 단위가 됩니다.

환경에 따라 LangGraph를 조건부로 가져오거나 서로 다른 실행 의미론을 아무런 표시 없이 선택해서는 안 됩니다.

## 11. 정규 테스트 경로

워크플로 테스트는 `app.llm`, `app.observability`, `app.workflow`를 직접 가져옵니다. 마일스톤 순서대로 이 정규 패키지를 생성하고 수정한 뒤 전체 워크플로 테스트 모음을 실행합니다.

```bash
uv run pytest -o addopts="" tests/workflow -q
```

구현 중에는 기호가 없으면 의존하는 테스트를 건너뛸 수 있습니다. 건너뛰기는 진행 상태 표시이지 인수 증거가 아닙니다.

## 12. 완료 게이트

결정론적 워크플로 테스트, 전체 저장소 테스트 스위트, Ruff, 형식 검사, 문서 동기화, 차이 정리가 통과하면 M4는 머신 검증을 완료한 것입니다. 사람이 유료 호출 플래그, 모델, 키를 명시적으로 제공하지 않는 한 선택적 실제 테스트는 계속 건너뛰어야 합니다.
