# M4 실측

이 결과는 결정론적 체크아웃과 오프라인 테스트를 설명합니다. 유료 공급자 요청은 실행하지 않았습니다.

## F1 — 잠긴 환경에 호환되는 LangGraph 설치가 없음

`pyproject.toml`과 `uv.lock` 모두 LangGraph를 포함하지 않으며, 활성 환경에서 `importlib.util.find_spec("langgraph")`는 `None`으로 확인됩니다. 따라서 M4는 추측에 근거한 의존성을 추가하는 대신 타입을 적용한 동등한 러너를 사용합니다.

그에 따른 영향은 의도적으로 작게 유지했습니다. R1에는 LangGraph 체크포인트 또는 시각화 API가 없습니다. 그 대신 모든 전이가 직접적인 Python 함수이고, 러너를 완전히 오프라인에서 테스트할 수 있으며, M5는 프레임워크 어댑터 없이 검색 및 공급자 의존성을 주입할 수 있습니다.

## F2 — 빈 증거는 모델에 절대 전달되지 않음

검색 결과가 청크 0개이면 `retrieve_node`가 `RetrievalEmpty`를 추가하고, 러너는 `grade`와 `check`를 모두 건너뛰며, `report_node`는 `NOT_IN_DOCS`를 반환합니다. 관찰된 노드 경로는 다음과 같습니다.

```text
retrieve -> report
```

그 결과 실행에는 공급자 요청과 추적 행이 모두 0개입니다. 이는 가장 큰 프롬프트 인젝션 표면을 제거합니다. 즉, 증거가 없을 때 모델에 답변을 만들어 내라고 요청하지 않습니다.

## F3 — 인용은 실행 가능한 허용 목록임

검사기가 제공받지 않았거나 관련 없음으로 평가된, 구문상 유효한 청크 ID를 반환할 수 있습니다. 코드는 해당 ID와 평가된 증거 집합의 교집합을 구합니다. 제거된 ID가 있으면 `CitationsFiltered` 사유가 생성되며, 남은 인용이 없는 `SUPPORTED` 답변은 등급을 낮추고 `SupportedWithoutCitations`를 추가합니다.

최종 인용 객체는 `chunk_id`, `doc_id`, 사람이 읽을 수 있는 인용, 반개방 출처 범위, `source_sha256`을 노출합니다. 따라서 M5는 답변 텍스트에서 증거 식별자를 재구성할 필요가 없습니다.

## F4 — 공급자 스키마 실패는 계속 거부로 처리됨

M4.1 단계는 엄격한 JSON을 검증하고, 검증 오류를 한 번 피드백한 뒤, 두 번째 실패 후 `schema_rejected`를 반환합니다. M4.3 단계는 타입이 지정된 이 결과를 `grade` 또는 `check` 추적으로 매핑하고, 최종 원시 출력과 재시도 횟수를 보존하며, `report_node`를 호출하지 않고 중단합니다.

잘못된 객체를 대체용 지원 답변으로 변환하지 않습니다. 공급자 거부, 공급자 오류, 검색 예외 역시 처리되지 않은 애플리케이션 트레이스백 대신 타입이 지정된 최종 보고서가 됩니다.

## F5 — 워크플로 예산은 모델 호출 전체에 걸쳐 누적됨

워크플로의 유일한 예산 검사는 각 노드 실행 직전에 이루어집니다. 전체 추적 튜플을 읽으므로 검사 전에 평가 사용량을 확인할 수 있고, 보고 전에 검사 사용량을 확인할 수 있습니다. 정확히 한도와 같아지면 남은 용량이 없으므로 다음 노드 실행이 거부됩니다.

결정론적 인수 테스트에서는 평가 단계에서 입력 토큰 허용량을 전부 소모합니다. 관찰된 결과는 `status="budget_exceeded"`, 경로 `retrieve -> grade`, 보존된 평가 추적 1개, `blocked_node="check"`입니다.

## F6 — 컨텍스트 제한은 증거 단위 전체를 제외함

워크플로는 검색 순서대로 `index_text` 문자를 세고 완전한 청크를 유지하거나 제외합니다. 부분 증거로 인해 프롬프트와 저장된 인용 범위가 분리될 수 있으므로 청크 본문을 자르지 않습니다. 제외할 때마다 정확한 청크 ID 및 구성된 문자 제한과 함께 `ContextTruncated`가 생성됩니다.

검색된 청크가 모두 제외되면 모델 호출 없이 `NOT_IN_DOCS`를 반환합니다. 축약된 컨텍스트를 조작하거나 그 사유를 숨기지 않습니다.

## F7 — 결정론적 검사와 유료 검사는 물리적으로 분리됨

오프라인 계약, 노드, 러너, 관찰 가능성, 공급자 테스트는 일반 `pytest`에서 실행됩니다. 실제 스모크 테스트는 `test_06_openai_live.py`에 있으며, 명시적 플래그, 모델 이름, 자격 증명이 모두 있어야 실행되고 그렇지 않으면 건너뜁니다.

현재 오프라인 체크포인트는 [검증](05-verify.md)에 기록되어 있습니다. 건너뛴 실제 테스트는 모델 접근, 답변 품질 또는 측정된 비용의 증거로 계산하지 않습니다.
