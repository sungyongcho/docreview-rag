# M7 실측

이 결과는 실행 가능한 로컬 증거와 외부 배포 주장을 구분합니다. 기록 날짜: 2026-08-13.

## F1 — 미리 준비된 모드는 환경 자격 증명보다 우선합니다

`ReleaseSettings`의 기본값은 `mode=canned`입니다. 환경에 있는 `OPENAI_API_KEY`는 마스킹된 구성 값으로 남지만 공급자 작업을 활성화하지 않습니다. 런타임 모드와 운영자 비밀 값이 모두 있어야 `openai_enabled`가 true가 됩니다. 공개 Gradio 화면에는 자격 증명 입력란이 없습니다.

이는 키의 존재 여부를 확인하는 것보다 강력합니다. 자격 증명이 있다고 해서 사용자가 비용 지출에 동의한 것은 아닙니다.

## F2 — 비용에는 명시적인 서버 측 상한 세 개가 있습니다

선택적 공급자 경계는 `gpt-4.1-mini`, 최대 입력 토큰 12,000 개, 최대 출력 토큰 600 개, 워크플로당 최대 예상 비용 `$0.01`을 사용합니다. 구성된 가격에서 토큰 상한에 따른 최대 예상 비용은 `$0.00576`으로 비용 상한보다 낮습니다.

입력 토큰 100만 개당 `$0.40`, 출력 토큰 100만 개당 `$1.60`이라는 가격 입력값은 2026-08-13 기준으로 공식 [`gpt-4.1-mini` 모델 페이지](https://developers.openai.com/api/docs/models/gpt-4.1-mini)에서 확인했습니다. 이는 영구적인 약속이 아니라 날짜가 명시된 구성이므로 승인된 실제 실행 전에 다시 확인해야 합니다. M7 인수 과정에서는 공급자 요청을 수행하지 않았습니다.

## F3 — 요청 제한기는 범위가 제한되며 의도적으로 단일 프로세스용입니다

각 클라이언트에는 이동식 minute/day 타임스탬프가 있습니다. 상태는 LRU 클라이언트 항목 1,024 개로 제한되며 저장된 식별자는 원시 주소가 아니라 키 기반 해시입니다. 동시 검사는 비동기 잠금 하나를 공유하므로 프로세스 하나에서 구성된 수만큼의 요청만 허용됩니다.

서로 다른 클라이언트가 매우 많이 유입되면 제거 때문에 클라이언트별 제한이 약해질 수 있으며, 여러 워커 또는 복제본은 각각 독립적인 카운터를 갖습니다. Docker Space 명령은 워커 하나로 고정합니다. 공개 확장에는 공유 외부 제한기가 필요하며, 여기서는 이를 갖췄다고 주장하지 않습니다.

## F4 — 보안 헤더는 정책 실패 응답도 포괄합니다

보안 헤더 미들웨어는 요청 가드 바깥에 등록됩니다. 테스트는 일반 응답, 읽기 전용 403, 요청 제한 429 응답에서 `x-content-type-options=nosniff`와 `cache-control=no-store`를 단언합니다. 가드가 생성한 응답은 안쪽의 헤더 계층을 우회할 수 있으므로 이 순서가 중요합니다.

Hugging Face는 Space를 iframe에서 렌더링하므로 제한적인 프레임 헤더를 추가하지 않습니다. 대신 릴리스는 same-origin 창 연결, same-site 리소스, no-referrer, no-store, 권한, no-sniff 정책을 사용합니다.

## F5 — 공급자 비밀 값은 서버 전용이며 영속화되지 않습니다

운영자 키는 `SecretStr`을 통해 읽고 공급자 생성자에만 전달하며 영속화 마스킹 대상에 추가하고 release/Uvicorn 로그 레코드에서 걸러냅니다. OpenAI 어댑터는 이미 `store=False`를 전송합니다. 공개 `/release` 메타데이터는 불리언 값과 고정된 상한만 노출합니다.

런타임 모드가 활성화된 동안 프로세스 메모리에는 비밀 값이 필연적으로 존재합니다. M7은 하드웨어 격리, 다중 테넌트 비밀 값 보관 또는 브라우저의 사용자 키 사용 흐름을 제공한다고 주장하지 않습니다.

## F6 — 클린 Git 증거의 코퍼스 범위는 더 좁습니다

`data/corpus/manifest.json`만 추적되며 SEC HTML 파일 20 개는 의도적으로 무시됩니다. 따라서 임시 클린 아카이브에서는 자체 완결적인 릴리스, 데모, API 스위트, 새 잠금 동기화, 린트, 문서화, Compose 검증, 두 컨테이너 빌드, 미리 준비된 health/UI 스모크 테스트를 실행합니다. 채워진 작업 저장소는 별도로 전체 오프라인 스위트를 담당합니다.

## F7 — 집중 통합 결과를 측정했습니다

결합된 `tests/release tests/demo tests/api` 게이트에서 `67 passed`가 측정되었습니다. 데이터베이스 또는 공급자 네트워크 호출 없이 M7 릴리스 테스트 21 개, M6 데모 테스트 6개, 기존 M5 API 표면을 포괄합니다. 채워진 저장소의 오프라인 스위트에서는 111.31 초에 `718 passed, 1 skipped`가 측정되었습니다. 그 후 새 임시 아카이브에서 잠금 의존성 동기화, 집중 테스트 67 개, 린트, 형식, 문서화 검사, 두 컨테이너 빌드, 미리 준비된 health/UI 스모크 테스트를 반복했고 모두 통과했습니다. 정확한 명령은 [검증](05-verify.md)에 기록되어 있습니다.
