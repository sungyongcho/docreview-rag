# M3 버그

## B01 — 청크 ID가 골든 식별자처럼 보였습니다

- **증상:** 원문 증거는 그대로인데 다시 청킹하자 모든 예상 답변이 달라졌습니다.
- **근본 원인:** 데이터베이스 청크 ID와 파서 순번은 구성에 따라 달라집니다.
- **수정:** 골든 답변은 `doc_id`, 원시 원문의 SHA-256, 반개구간 원문 오프셋을 사용합니다.
- **방지책:** 로더 및 채점 테스트는 소스/해시 불일치를 거부하고, 청크 식별자가 달라진 뒤에도 동등한 원문 포함 범위의 점수가 같음을 검증합니다.

## B02 — 부재 사례가 검색 지표를 낮췄습니다

- **증상:** 부재 주장에 대한 올바른 미검색 결과가 재현율 없음으로 나타났습니다.
- **근본 원인:** 부재에는 양성 범위가 없으므로 범위 재현율은 0이 아니라 정의되지 않습니다.
- **수정:** 모든 사례를 검색하고 기록하되 원문 근거가 있는 양성 사례만 채점하고, 부재 사례에는 `score=null`을 저장합니다.
- **방지책:** 러너 테스트는 기록된 사례 28개, 채점된 양성 사례 24개, 채점되지 않은 부재 사례 네 개를 요구합니다.

## B03 — 완전한 질문에서 어휘 후보가 나오지 않았습니다

- **증상:** 두 어휘 실험군 모두 검색 결과 없음, Recall@5 없음, 빈 원시 검색 결과 목록을 측정했습니다.
- **근본 원인:** `websearch_to_tsquery`가 대표 질문에서 남은 어휘소를 AND로 결합했으며, 모든 용어를 포함한 청크가 없었습니다. 이는 검색 결과이지 채점기나 산출물의 실패가 아닙니다.
- **M3 수정:** 없습니다. 이 발견은 측정이 의도대로 동작한 결과입니다. 수정은 이후 M2.4에 들어갔습니다. 파싱된 논리곱을 논리합으로 완화하고 `ts_rank_cd` 정규화 `4 | 1`을 걸어 어휘 실험군을 recall@5 0.000에서 0.271로 올렸으며, BM25는 0.521로 계속 앞섭니다.
- **방지책:** 보고서는 이 한계를 명시하며 하이브리드/벡터 동일성을 의미적 동등성으로 해석하지 않습니다.

## B04 — 타이머가 처음에는 파싱과 청킹을 제외했습니다

- **증상:** 초기 로컬 예산 파일이 임시 DDL, 영속화, 임베딩 시간만 보고했습니다.
- **근본 원인:** `build_chunking_batch()`가 반환된 뒤 시계를 시작했습니다.
- **수정:** 매니페스트 로드, 파싱, 청킹 전에 단조 증가 시작 시간을 수집한 다음 임시 코퍼스 세션에 전달합니다. 전체 행렬을 다시 생성합니다.
- **방지책:** 수정된 `20260812T200916Z` 산출물만 커밋합니다. 대체된 부분 타이밍 파일은 포트폴리오 증거로 오인되지 않도록 제거했습니다.

## B05 — 채워진 벡터에서 공급자 식별 정보를 추론할 수 있었습니다

- **증상:** 실험이 기존 벡터를 현재 환경이나 쿼리 공급자의 것으로 표시할 위험이 있었습니다.
- **근본 원인:** 채워진 청크 스키마는 임베딩 공급자 식별 정보를 영속화하지 않습니다.
- **수정:** 모든 실험은 명시적인 공급자로 자체 임시 코퍼스를 생성하고 임베딩합니다. 기존 공급자 식별 정보는 알 수 없는 상태로 유지합니다.
- **방지책:** 구성과 산출물은 공급자, 차원, 유료 호출 상태, 환경, `populated_corpus_embeddings_modified=false`를 기록합니다. 검증 과정은 실행 후 공개 청크 수와 null이 아닌 임베딩 수를 다시 확인합니다.

## B06 — 구성 키 순서가 기준선을 나누거나 합쳤습니다

- **증상:** 동등한 딕셔너리가 기준선을 놓칠 수 있었고, 불완전한 구성은 의미 있는 변수가 달라진 실험끼리 비교할 수 있었습니다.
- **근본 원인:** 비교가 완전한 정규 구성이 아니라 호출자의 표현에 의존했습니다.
- **수정:** 유한 JSON을 검증하고 모든 객체 키를 정렬하며 전체 중첩 청킹/검색/임베딩/측정 구성을 영속화합니다.
- **방지책:** 회귀 테스트는 중첩 정규 직렬화, 정확한 스위트/구성 대조, 최신 항목 순서, 비교할 수 없는 구성을 다룹니다.

## B07 — 지연 시간을 실수로 클수록 좋은 값으로 취급했습니다

- **증상:** 모든 수치 지표가 하나의 비교 규칙을 공유하여 더 느린 실행이 개선된 것처럼 보일 수 있었습니다.
- **근본 원인:** 지표 방향이 암묵적이었습니다.
- **수정:** 회귀 비교는 명시적으로 클수록 좋은 튜플 `recall_at_k`, `hit_rate_at_k`, `mrr`만 받습니다. 지연 시간은 계속 관측하지만 별도의 상한 예산으로 관리합니다.
- **방지책:** 순수 비교 테스트는 추가 지표가 무시되고 허용 오차 경곗값이 포함됨을 검증합니다.

## B08 — 기계 검사를 사람의 검토로 오인할 수 있었습니다

- **증상:** 유효한 해시와 범위를 작성자가 승인한 골든 답변으로 설명했습니다.
- **근본 원인:** 구조 검증과 편집 판단을 혼동했습니다.
- **수정:** 리터럴 선별, 승인, 사람 검증 필드를 모든 원시 산출물과 보고서에 포함합니다.
- **방지책:** 로더와 러너는 출처가 혼합되었거나 사람이 검증했다고 주장하는 모든 M3 사례를 거부합니다. 작성자 검토는 중단 게이트로 유지됩니다.
