## 1. 도메인 = 반도체 기업 재무 공시 (SEC 10-K)

### 코퍼스 (확정 · 스냅샷 고정)

| | Core (R1) | 확장 (R1.2) |
|---|---|---|
| **코퍼스** | **SEC 10-K 영어** — NVIDIA · AMD · Intel · Micron (2020~2024, 4사×5년 = **20건**) | + DART 한국어(삼성/SK하이닉스) · + 20-F(TSMC/ASML) |
| **강점** | retrieval 품질 · eval · 가드레일 | + cross-lingual · + 소스 양식 확장 |

- **소스:** SEC EDGAR 무료 API(`data.sec.gov`). **스냅샷 고정** — 문서가 바뀌면 평가가 흔들린다
- **Core = 미국 10-K 단일 양식** → 동종 비교가 자연스럽고 파서가 하나면 된다
- **양:** 20건 = 청크 수천~1.5만. ingestion·검색은 자동이라 감당된다. **병목은 골든셋(수작업)** → 코퍼스 전체 커버 말고 [대표 질문 24~30개 선별](02-design.md#골든셋-포맷-datagoldenretrievaljson)

### 왜 이 도메인인가 (흥미가 아니라 기술 임팩트로 선택)

| 기술 쇼케이스 | 반도체 10-K가 주는 것 |
|---|---|
| **ingestion 깊이** | **표·재무제표 파싱**(RAG 진짜 난제) + 긴 문서 + 계층 구조(Item 1/7/8…) |
| **retrieval 깊이** | 정확 숫자 검색("2024 R&D 지출")에 벡터가 약하다 → **하이브리드가 도메인에서 정당화된다** |
| **multi-hop** | 기업간·연도간 비교("NVIDIA vs AMD R&D") |
| **eval 깊이** | 숫자 정답이 명확 → 골든셋 제작·검증이 쉽다 |
| **가드레일** | 없는 수치·연도 → `NOT_IN_DOCS`. **환각이 금융에선 치명적**이라 실용적 정당성이 있다 |
| **대비 데모** | "NVIDIA 2024 R&D?" → general LLM 환각/뭉갬 **vs** 우리 시스템 인용+정확 |

**수용된 트레이드오프:** 재무 용어를 약간 배워야 한다(매출·R&D·부채 수준).

## 2. Narrative — "나는 개발자다"

**포지셔닝 한 줄:**
> *"An engineer's take on the hardest RAG data type — retrieving accurately from financial filings, evaluating its own quality, and refusing to hallucinate."*

| 절대 안 하는 것 | 하는 것 |
|---|---|
| "금융 인사이트 도구" / "투자 조언" 척 | "개발자가 RAG에서 제일 어려운 데이터(표·숫자·긴 문서·비교)를 기술적으로 정복" |
| (금융 전문가와 경쟁 + "너 금융 알아?" 리스크 + 과장) | **엔지니어링이 주인공** |

이건 `jobs/rules/01-positioning.md`의 **"AI/ML 인프라 + 백엔드"** 정체성과 일치한다. 새 정체성을 만들지 않는다 — 워딩만 맞춘다.

### 이 도메인이 여는 기술 스토리 (문서·면접용)

- "재무제표 **표**를 어떻게 청킹·인덱싱했나" (남들이 회피하는 부분)
- "정확 숫자 질문에서 벡터가 왜 실패하고 하이브리드가 왜 이기나" — **ablation 숫자로**
- "기업간 비교(multi-hop)를 어떻게 풀었나"
- "없는 수치를 지어내지 않게 어떻게 **강제**했나" — 프롬프트가 아니라 코드로
- "retrieval 품질을 어떻게 측정·회귀감지했나"
- (확장) "한국어 질문으로 영어 filing을 어떻게 검색하나"

## 3. 정직한 워딩

- **"production-ready" 금지.** 배포되고 실사용자가 있고 운영되지 않는 한 쓰지 않는다
- 재무 도메인 전문가가 아님을 문서에 **명시**
- 시스템이 **하는 것 / 안 하는 것**을 구분해서 적는다
- 데모와 풀 시스템의 차이를 [명시](#7-배포--비용-제약)한다

## 4. 의도적 직접 구현 결정

> **"왜 기성 라이브러리 안 쓰고 돌아가지?"를 미리 차단한다.** 이 프로젝트는 학습·역량 증명 목적이라 RAG 핵심 로직을 **의도적으로 직접 구현**한다. 게으름이 아니라 선택.

| 직접 구현 | 대신 안 쓰는 것 | 이유 |
|---|---|---|
| **10-K 파싱: BeautifulSoup + lxml** | `sec-parser` · `edgartools` | 표 파싱·섹션 자르기가 이 프로젝트의 **star**. 전용 파서 쓰면 그 역량이 안 보인다 |
| 청킹 · 인용 매핑 | LangChain 고수준 splitter/QA chain | 청킹 전략이 retrieval 품질을 좌우 → 직접 통제·설명 가능해야 |
| 하이브리드 · RRF · 리랭크 조합 | 프레임워크 retriever | 검색 품질이 차별점. 스코어링을 직접 |
| eval 채점 | Ragas (비교 경로만 문서화) | 지표 로직을 직접 이해·테스트해야 한다 |

**경계 — 기성품을 쓰는 것:** 임베딩 · 리랭커 · LLM · LangGraph(오케스트레이션 한 곳) · LangChain(구조화 출력 경계 한 곳). **직접 구현 = 파이프라인 로직 / 기성품 = 모델·경계 프레임워크.**

**표준 문구 (README · 모듈 docstring):**
> `For education/practice purposes, core RAG logic (10-K parsing, chunking, retrieval, eval) is implemented` `directly with BeautifulSoup+lxml / SQLAlchemy / pytest instead of higher-level libraries, to keep the` `retrieval-quality and ingestion logic inspectable rather than hidden behind a framework.`

## 5. 데모 UX

목적: **구인자가 assess하기 친절하게.** 5초 안에 "뭐고 왜 소용"이 오게.

### 예시 질문 = 골든셋과 한 몸

"어떤 질문을 보여줄지"는 별도 작업이 아니라 **골든셋 설계의 부산물**이다. [골든셋 각 항목에 `demo-hero`·`category` 태그를 라벨링과 동시에 붙인다](02-design.md#골든셋-포맷-datagoldenretrievaljson). → 하이라이트를 뽑으면 그게 데모 예시. **canned로 미리 계산**(비용 0).

| 카테고리 | 예시 | 보여주는 것 |
|---|---|---|
| 단순 조회 | "NVIDIA 2024 총매출은?" | 기본 동작 |
| **정확 숫자** | "NVIDIA 2024 R&D 지출?" | 벡터가 약한 지점 → 하이브리드 시연 |
| **multi-hop 비교** | "NVIDIA vs AMD 2024 R&D" | 기업간 비교 |
| **부재/함정** | "NVIDIA 2024 배당 성향?" | `NOT_IN_DOCS` — **가드레일 hero** |
| **대비 hero** | general LLM이 환각하는 특정 수치 | 환각 vs 인용+정확 |

### 온보딩 4요소

1. **prefilled 예시 질문 (클릭 가능)** ← 제일 중요. 뭘 물을지 몰라도 클릭 한 번에 wow 2. **1줄 설명** — "재무 공시(10-K)에서 정확한 근거로 답하는 RAG. general LLM과 비교해보세요" 3. **대비 데모** — 같은 질문에 general LLM(환각) vs 이 시스템(인용+정확) 나란히 4. **기술 투명성 토글** — retrieval 결과·score·어느 filing 어느 Item·node path(retrieve→grade→check)· [실패 사유](02-design.md#7-실패-모드-피드백) 노출 → **"블랙박스 아님"의 증명**

### UX 원칙

① 5초 안에 "뭐고 왜 소용" · ② 결과에 **항상 인용** · ③ 정직("개발자가 만든 RAG 엔지니어링 데모", 금융 조언 아님) · ④ 저비용([§7](#7-배포--비용-제약))

## 6. 문서화 (데모보다 우선)

**두 관문이 있다:**

| | 관문 1 — 리크루터 (6초) | 관문 2 — hiring manager (심층) |
|---|---|---|
| 무엇으로 | 배포된 데모 · 대비 데모 · README 첫 화면 | **문서** — "어떻게 생각했나" |
| 결정하는 것 | 다음 단계로 넘길지 | **채용 여부** |

**관문 2가 채용을 결정하고, 그건 데모가 아니라 문서에서 갈린다.** 백엔드/RAG role은 결과물보다 "어떻게 생각했나"가 중요하다.

- **형태:** GitHub README(영문) + `docs/*.md` (필수) + 문서 사이트(재활용, 나중)
- **담을 것:** 학습 여정 · 아키텍처 · **retrieval 품질 실험(ablation·eval 숫자)** · 표 파싱 전략 · 가드레일 설계 · 의사결정 노트 · failure analysis · 한계
- **README 섹션은 [#16](01-requirements.md#16-리포-위생과-영문-readme)의 고정 목록을 따른다**
- **우선순위: 콘텐츠(실험·기록) 먼저 → 사이트화 나중.** Gradio = 기능 데모, 세련된 룩은 문서 사이트가 담당

## 7. 배포 · 비용 제약

### 원칙: 데모 ≠ 풀 시스템

| | 풀 시스템 (GitHub + 문서) | 배포 데모 (공개 웹) |
|---|---|---|
| 목적 | 기술 쇼케이스 (pgvector·하이브리드·리랭커·eval·워커) | 방문자 인터랙션 |
| 비용 | 로컬 = 무관 | **저비용 필수** |
| LLM | 실제 실행 | **canned 위주 + 최소** |

→ 풀 시스템은 코드·문서로 증명하고, 배포 데모는 가벼운 버전으로 간다. **이 차이를 문서에 정직하게 적는다.**

### 토큰 절감

- **Canned** — 골든/대표 질문은 결과를 미리 계산·저장 → 방문자는 저장본 (LLM 호출 0). 대비 데모의 "general LLM 환각" 예시도 미리 계산
- **Exact-match 캐시** — 정규화 질문 해시를 키로 (R1.1)
- **BYO-key** — 자유 질문은 방문자 본인 키
- **작은 모델 + `max_tokens` 제한 + 짧은 프롬프트** ([#15](01-requirements.md#15-작은-모델--제약--큰-모델--01-v5))
- **[예산 강제](02-design.md#5-예산-강제)가 그대로 비용 가드다** — 같은 코드
- **Rate limit** — 분당 N개, IP당 일 상한. 실제 값은 배포 후 트래픽 보고 조정

> **semantic 캐시는 안 한다.** 금융은 엔티티·연도·지표가 답을 결정해서 특히 위험하다 ("Apple 2024 R&D" ≈ "Apple 2023 R&D"는 임베딩상 가깝지만 답이 다르다 → 캐시 오염). exact-match만 확정. 정규화 키(엔티티+연도+지표 추출) 방식은 실제 질문 패턴을 본 뒤 재검토.

### 인스턴스 절감

- **임베딩을 API로 or 미리 계산** → 로컬 모델 상주 불필요 = 낮은 인스턴스. **이게 [3.14/torch 블로커](00-plan.md#2-착수-전-블로커-m2-첫날-해소)의 해법이기도 하다**
- **리랭커(무거움)는 데모에서 끈다** — ablation 비교군으로만 존재
- **데모는 동기 in-process** (워커·redis 없이). 풀 시스템의 async는 문서·로컬로 증명
- **DB** = managed 무료 티어 or 데모용 작은 코퍼스

### 배포처

HF Spaces (Gradio) + 문서 사이트에서 iframe 임베드/링크.

## 8. 다국어 · 소스 확장 (R1.2)

**"동일 criteria" 원칙:** 파서 입구(SEC/DART/20-F)만 소스별 어댑터를 두고, 정규화 후 파이프라인(청킹·임베딩·검색·워크플로우·eval)은 **전부 공유**한다.

- 순서: **영어 SEC 완성·검증 후에만.** 아니면 star(retrieval 품질)가 흐려진다
- cross-lingual retrieval도 retrieval 품질의 한 차원이다 — "한국어로 물어도 영어 filing에서 정확히 찾나"
- 같은 원리로 **코드/문서 코퍼스 어댑터**도 가능 → 어댑터 패턴의 실증

**범위 밖:** GraphRAG (문서에 "다음 확장"으로 명시만).
