# 결과를 비교하고 검색 데이터 보관하기

평가 결과는 측정값과 설정을 기록합니다. 스냅샷은 선택한 평가 결과와 검색 데이터를 함께 보존해 확인한 구성을 다시 실행 없이 재사용하고 비교할 수 있게 합니다. 찾기, 상세, 비교, 적용, 게시 순으로 읽고, [새 스냅샷 저장](#step-12)은 맞는 기존 스냅샷이 없을 때만 필요한 조건부 단계입니다.

| 작업 | 위치 |
|---|---|
| 저장된 스냅샷 찾기 | [스냅샷 관리](#management)의 필터·검색·정렬 |
| 기록 내용 확인 | [스냅샷 상세](#snapshot-details) 패널 |
| 저장된 스냅샷 두 개 비교 | [저장된 결과 비교](#comparison)와 문항별 변화 |
| 새 결과 보존 | 맞는 스냅샷이 없을 때 [스냅샷 저장](#step-12) |
| 고정된 검색 상태로 조회 | 질문 전송 없이 [적용](#save) |
| 방문자에게 공개 | [게시·숨기기](#visibility) |
| 내 데이터 없이 체험 | [공개 예시](#public-comparisons) |

## 저장 스냅샷 찾기 {#management}

**품질 검증 → 4. 비교·스냅샷 → 스냅샷 관리**를 엽니다. **결과 비교**와 **스냅샷 관리**는 구분되며, 평가 결과끼리 비교할 때는 스냅샷이 필요 없습니다. 방문자에게는 같은 목록이 **게시된 스냅샷**으로 표시되고 상세와 저장된 결과 비교도 그대로 제공되지만, 개발 전용인 적용·공개 동작은 없습니다.

1. **데이터셋 파일**로 **저장 스냅샷**을 좁히거나 **검색**에 파일명·스냅샷 이름을 입력하고 **정렬 기준**에서 최신순·오래된순·이름·파일명을 고릅니다.
2. 카드에서 이름·기록된 검색 설정·근거 발견율을 읽습니다. 개발 모드 카드에는 공개·비공개 배지가 더해집니다.
3. 카드를 눌러 오른쪽에 **스냅샷 상세** 패널을 엽니다.

**저장 스냅샷** 수가 `0 / N`이고 "조건에 맞는 스냅샷이 없습니다"가 보이면 필터가 모든 항목을 숨긴 것이므로 검색어나 파일 필터를 지우세요. "저장된 스냅샷이 없습니다"는 아직 만든 스냅샷이 없다는 뜻입니다. 이 화면에는 스냅샷별 삭제·이름 변경 동작이 없으며, 스냅샷은 DB에 보관되고 실행 데이터 초기화 시 삭제됩니다.

### 스냅샷 상세 {#snapshot-details}

패널에서 스냅샷이 기록한 내용을 확인하고 동작을 실행합니다.

| 읽을 항목 | 확인 내용 |
|---|---|
| 이름과 배지 | 스냅샷 이름과 공개·비공개 상태입니다. |
| 데이터셋 파일·검색 설정 | 점수의 바탕이 된 질문과 기록된 검색 구성입니다. |
| **기준 평가 보기** | 정확한 원본 결과를 엽니다. 숫자 ID 대신 문구 링크로 표시하며 개발 모드 전용입니다. |
| 문서·생성 시각 | 포함된 문서 수와 만든 시각입니다. |
| 저장된 지표 | 기록된 측정값입니다. |
| 기록된 설정 | 코퍼스 식별값·원본 검색 프로필·평가 구성으로, 비교를 신뢰하기 전 확인할 식별 정보입니다. |

| 동작 | 효과 |
|---|---|
| **대화에 적용** | 보관한 검색 구성을 적용하고 스냅샷을 선택하며 질문을 보내지 않습니다. 준비된 스냅샷에서만 활성화되는 개발 전용 동작입니다. |
| **게시** · **숨기기** | 별도의 명시적 동작으로 공개 상태를 바꾸는 개발 전용 동작입니다. [공개 범위](#visibility)를 참고하세요. |

X·**닫기** 버튼·Escape 키·배경을 눌러 패널을 닫습니다.

<!-- details: management-filters | 필터·식별자·보존 참고 -->
스냅샷 관리는 평가 실행 목록과 같은 데이터셋 파일명을 사용합니다. 평가 결과 하나에는 스냅샷 하나만 연결됩니다. 저장 후 결과 화면은 **저장된 스냅샷 보기**를 표시하고, 같은 결과를 다시 저장해도 이름·공개 상태를 바꾸지 않고 기존 스냅샷을 반환합니다. 내부 식별자는 기록된 설정 안에서 확인할 수 있습니다. 골든셋 파일의 보존 정책은 별도입니다.

## 저장된 결과 비교와 조건 읽기 {#comparison}

**스냅샷 관리** 목록 위의 **스냅샷 비교**에서 기준과 후보를 고른 뒤 **저장된 결과 비교**를 누릅니다. 스냅샷 두 개의 비교는 저장된 산출물만 읽으며 검색·평가·모델 호출을 실행하지 않습니다. 같은 비교는 페이지에서 재사용하고 문항 목록은 페이지로 나눕니다. 공개 산출물 조회와 비교 응답은 크기 제한이 있고 초과하면 명시적 오류를 표시합니다. 서로 다른 두 스냅샷을 고르세요. 같은 스냅샷을 두 번 선택하면 버튼이 비활성화되고 안내가 표시됩니다.

**스냅샷 비교** 패널은 지표 표 앞에 **직접 비교 가능** 또는 **제한적인 비교** 배지와 경고를 표시합니다. 직접 비교 가능 여부는 suite와 정답 식별자를 검사합니다. 같은 이름만으로 통제된 실험이 되지 않으므로 차이를 특정 설정의 효과로 해석하기 전에 corpus·임베딩 식별자·검색 설정·`k`를 확인하세요. 지표 행은 기준·후보·변화를 보여 주고, 제한적인 비교에서 계산할 수 없는 차이는 `해당 없음`으로 표시됩니다.

<!-- details: compatibility-reference | 차이를 해석하기 전 확인할 항목 -->
| 확인할 항목 | 중요한 이유 |
|---|---|
| Suite와 정답 버전·해시 | 질문이나 정답 원문 범위가 바뀌면 점수가 측정하는 대상도 달라집니다. |
| Corpus 식별자와 문서 수 | 검색 대상이 늘거나 바뀌어 근거를 더 잘 찾았을 수 있습니다. |
| 임베딩 제공자·모델·차원 | 벡터 식별자가 저장 데이터가 지원하는 검색 구성을 정합니다. |
| 검색 방식·`k`·후보 수·재정렬 | 반환 근거와 작업량이 늘면 품질과 지연 시간 모두 달라질 수 있습니다. |
| 문항별 변화 | 평균 향상 뒤에 중요한 퇴보가 숨어 있을 수 있습니다. |

결과 비교 선택 아래의 **예시 보기** 접이식은 설명용으로 명시되어 있으며 기록된 결과가 아닙니다.

### 공통 문항과 순위 변화 {#case-changes}

공통 문항 목록은 각 문항의 양쪽 질문과 첫 번째 관련 근거 순위(없으면 미적중), 전환 상태, 순위 변화를 함께 보여 줍니다. **검색 실패 → 성공**은 개선, **검색 성공 → 실패**는 퇴보입니다. 검색 성공 유지·검색 실패 유지는 적중 여부가 같다는 뜻이며, 성공한 문항의 순위는 달라질 수 있습니다. 순위 변화는 후보 순위에서 기준 순위를 뺀 값으로, 스냅샷이 직접 비교 가능하고 두 순위가 모두 있을 때만 표시됩니다. 5위에서 2위로 오르면 −3으로 표시되며 더 빠른 순위라 개선입니다. 공통 문항이 없으면 같은 문항을 기준으로 비교할 근거가 없습니다.

**결과 비교**의 평가 결과 비교도 같은 방식으로 읽되 같은 데이터셋의 서로 다른 결과 두 개가 필요합니다.

## 결과를 비교하고 적합한 스냅샷 저장하기 {#step-12}

> [!GOAL]
> 평가 결과 두 건을 비교하고 나중에 다시 쓸 수 있게 이름 붙인 스냅샷으로 저장합니다.
>
> **준비** 현재 인덱스와 원문이 일치하는 성공한 **빠른 평가 · 현재 인덱스** 결과 · **완료** 호환성과 이름이 기록된 저장 스냅샷

> [!DEV]
> 비공개 평가 결과 비교와 새 스냅샷 저장은 개발 모드 전용입니다. 방문자에게 게시된 스냅샷 비교는 별도의 공개 기능입니다.

새 스냅샷이 필요할 때만 이 단계를 진행합니다. 기존 스냅샷을 적용하거나 비교하는 작업에는 필요 없습니다. 근거와 실험 조건을 보고 결과를 선택한 뒤 나중에 사용할 수 있게 보관합니다. 현재 인덱스와 원문 corpus가 일치하는 성공한 **빠른 평가 · 현재 인덱스** 결과가 한 건 이상 있어야 합니다. 비교에는 서로 다른 결과 두 개가 필요합니다. 한 건뿐이라면 그 결과를 읽고 비교할 수 없는 상태를 그대로 받아들이며 지표를 임의로 만들지 않습니다. 화면을 채우기 위해 유료 평가를 추가하지 않습니다.

1. **품질 검증 → 4. 비교·스냅샷 → 결과 비교**를 열고 기준과 후보를 선택합니다. **선택한 결과 비교** 전에 메타데이터를 읽습니다.

| 입력 | 의미 |
|---|---|
| 기준 | 개선의 출발점으로 삼을 결과입니다. |
| 후보 | 기준과 비교할 다른 결과입니다. |
| 데이터셋·버전 | 점수의 바탕이 되는 질문과 정답 근거를 식별합니다. |
| 스냅샷 이름 | `SEC hybrid k5 baseline`처럼 알아볼 수 있는 이름입니다. 이름만으로 호환성을 판단하지 않습니다. |

2. 지표와 함께 달라진 문항·지연 시간을 확인합니다.
3. **3. 평가 실행**으로 돌아가 적합한 결과를 선택하고 **결과 상세**를 엽니다.
4. 이름을 입력하고 **결과를 스냅샷으로 저장**합니다. 저장만으로는 게시되지 않습니다.

저장은 결과를 현재 문서·청크·벡터·키워드 인덱스 데이터에 연결합니다. 서버는 평가에 기록된 원문 fingerprint와 현재 인덱스가 일치하는지 확인하므로 현재 인덱스를 사용한 빠른 평가만 저장할 수 있습니다. 정답 리비전이 연결된 경우 게시된 버전이고 평가의 정답 해시와 일치해야 합니다. 스냅샷 생성 알림이 나오고 처음에는 비공개이며 결과 화면에는 **저장된 스냅샷 보기**가 표시됩니다. 같은 결과를 다시 저장하면 이름이나 공개 상태를 바꾸지 않고 기존 스냅샷을 반환합니다. [스냅샷 관리](#management)에서 이름·문서 수·suite·결과 ID를 확인하세요.

저장된 식별 정보가 의도한 결과와 맞고 저장 스냅샷 목록에서 확인할 수 있으며 비교 한계를 이해했으면 완료입니다. 평가 이후 원문 corpus가 바뀌었거나 조합별 평가 결과를 현재 인덱스용 검색 스냅샷으로 저장하려는 경우에는 오류를 읽고 일치하는 빠른 평가 결과를 고르거나 의도한 현재 corpus를 평가합니다. [평가·스냅샷 복구](troubleshooting.md#evaluation)를 참고하세요.

이어서 [보존하며 종료하고 다시 시작하기](runtime.md#resume)를 보거나, [답변](answers.md)으로 돌아가 다음 요청 전 적용된 스냅샷을 확인합니다.

## 스냅샷 적용과 현재 corpus 복귀 {#save}

결과 상세의 **선택 설정 적용**은 결과의 검색 설정을 적용합니다. 저장 스냅샷의 **대화에 적용**은 보관한 검색 구성을 적용하고 스냅샷을 선택해, 그 대화가 실제 corpus 대신 고정된 스냅샷 데이터를 조회하게 합니다. 스냅샷이 준비될 때까지 비활성화됩니다. 둘 다 대화를 준비할 뿐 검토를 실행하거나 질문을 전송하지 않습니다.

**요청 보기**로 다음 요청을 확인하고, 현재 corpus로 돌아가려면 스냅샷 칩을 의도적으로 해제하세요. 스냅샷은 애플리케이션 전체나 브라우저 대화·인증 정보를 백업하는 기능이 아니므로 원문과 일반 백업은 필요한 보존 정책에 따라 별도로 관리하세요.

## 비공개 저장과 공개 범위 {#visibility}

> [!DEV]
> 게시·숨기기는 스냅샷 공개 상태를 바꾸며 개발 모드 전용입니다. 게시된 스냅샷과 소속 문서를 읽는 동작은 공개 상태를 바꾸지 않습니다.

저장된 스냅샷은 항상 비공개로 시작합니다. **게시**와 **숨기기**는 스냅샷 상세 패널의 별도 명시적 동작입니다. 게시하면 준비된 스냅샷과 조건을 충족하는 문서 목록을 방문자가 읽을 수 있고, 숨기면 그 스냅샷이 공개 목록에서 빠집니다. 공개 여부를 바꾸기 전에 범위를 확인하세요. 로컬 평가·실험 저장·결과 읽기에는 게시가 필요하지 않습니다.

공개 문서 목록·필터 선택지·개수·상세는 준비된 공개 스냅샷 소속과 정확한 원문 식별자를 기준으로 합니다. 한 스냅샷을 숨겨도 다른 공개 스냅샷에 속한 문서는 계속 공개될 수 있습니다. 회사 메타데이터도 같은 공개 범위를 따라야 합니다. 개발 DB에 문서가 많아도 게시된 스냅샷이 없으면 공개 문서 목록이 비어 있는 것이 정상입니다.

## 대화형 공개 비교 {#public-comparisons}

방문자는 게시된 스냅샷을 읽고 저장된 기록을 비교할 수 있으며, 역시 검색·평가·모델을 실행하지 않습니다. **예시로 체험하기**를 누르면 기존 3문항 중 2개와 3개가 적중하는 설명 사례를 엽니다. 같은 비교 화면에서 기준을 반대로 바꾸고 문항을 검색하며 순위 변화를 펼쳐봅니다. 설명용 자료이며 실제 평가가 아닙니다. 실험 파라미터를 바꿔도 점수를 만들거나 바꾸지 않습니다. 실제 조회 실패·자료 없음 상태를 예시로 자동 대체하지 않습니다.
