# DocReview RAG 사용 안내

DocReview는 SEC·DART 공시를 검색해 원문으로 검증할 수 있는 답변을 만듭니다. 답변의 주장을 인용문까지 따라가고, 그 근거를 찾은 검색 결과를 살펴보며, 기록된 검색 평가를 비교할 수 있습니다. 매뉴얼은 이 작업이 여러 화면으로 이어지는 흐름을 설명하고, 도움말은 사용 중인 조작 항목의 의미를 설명합니다.

실행 중인 서비스를 체험하려면 [Quick Start](quickstart.md), 새 clone을 실행하려면 [환경 준비](environment.md#qs-setup)에서 시작하세요. 17개 가이드는 DEV와 PROD에서 모두 읽을 수 있으며, DEV 표시는 개발 환경에서 실행해야 하는 작업을 뜻합니다.

## 시작할 곳 {#start}

| 현재 상태 | 따라갈 경로 | 얻는 결과 |
|---|---|---|
| 실행 중인 공개 서비스 | [Quick Start](quickstart.md) → [답변](answers.md) → [문서](documents.md)와 [스냅샷](snapshots.md) | 근거가 있는 답변을 읽고 원문을 검증하며 공개 결과를 살펴봅니다. |
| 새 clone 또는 빈 로컬 DB | [환경 준비](environment.md#qs-setup) → [Quick Start for DEV MODE](quickstart-dev.md) | DEV를 실행하고 예제 공시 두 건을 검색할 수 있게 준비합니다. |
| 기존 로컬 코퍼스 | [문서](documents.md#step-2) → 빠진 [준비 단계](quickstart-dev.md) | 다운로드한 원문, 청크, 설정과 일치하는 임베딩, BM25를 재사용합니다. |

공개 포트폴리오는 NVIDIA·AMD FY2019–FY2024와 삼성전자·SK하이닉스 FY2022–FY2024의 공시 18건을 다룹니다. 새 DEV 설치에는 이 준비된 DB 행이나 다운로드 원문이 따라오지 않습니다. 기본 공시 선택은 준비할 범위를 나타내며, 작업이 실행됐다는 증거는 아닙니다.

필터 결과가 없는 상태와 공개 문서가 없는 상태도 DB 전체가 빈 상태와 다릅니다. 무엇이 부족한지 판단하기 전에 현재 필터와 [문서 공개 범위](documents.md#visibility)를 확인하세요.

CLI와 Web은 같은 DB·원문 디렉터리·실제 설정을 사용할 때 결과를 공유합니다. 코퍼스 helper는 데이터 준비 화면과 같은 작업을 제출하며, 대기열을 거치지 않는 직접 실행 도구에는 작업 기록이 없을 수 있습니다. 다운로드·적재·인덱스 생성·유료 모델 호출을 반복하기 전에 완료된 결과를 확인하세요.

## 열두 단계 학습 경로 {#learning-path}

전체 로컬 실습은 아래 순서로 진행합니다. 내비게이션은 사용법을 준비 작업보다 먼저 묶어 보여 주지만, 단계 번호는 실행 순서를 유지합니다. [Part 1: 환경 준비](environment.md#qs-setup)에서 시작해 [DEV 준비](quickstart-dev.md), 검색, 답변, 설정, 평가로 이어가세요. 같은 환경에서 완료한 작업은 건너뜁니다.

<!-- tutorial-steps -->

파싱으로 만든 청크는 의미 검색용 임베딩과 키워드 검색용 BM25에 각각 사용됩니다. 하이브리드 검색은 두 인덱스가 모두 필요하고, 벡터 검색은 설정과 일치하는 임베딩, 키워드 검색은 BM25가 필요합니다. 평가에는 정답 근거가 지정된 데이터셋도 필요합니다. 답변 생성 전에 검색부터 평가할 수 있습니다.

## 작업에 맞는 화면 찾기 {#workspaces}

| 화면 | 작업과 결과 |
|---|---|
| 대화 | 범위를 정해 질문하고 실행을 지켜본 뒤 인용과 검색 후보로 주장을 검증합니다. |
| 데이터 준비 → 파이프라인 | 준비 단계의 의존 관계를 확인하고 DEV에서 빠진 단계를 실행합니다. 노드를 선택하면 해당 단계만 열립니다. |
| 데이터 준비 → 문서 | 공시를 찾아 식별 정보와 청크를 읽고 저장된 임베딩 준비 상태를 확인합니다. |
| 데이터 준비 → 작업 | 제출한 작업의 진행, 완료, 기록된 오류, 명시적 재시도를 확인합니다. |
| 품질 검증 | DEV에서 검색과 평가를 실행하고, PROD에서는 공개 스냅샷과 비교 결과를 살펴봅니다. |
| 시스템 → 시스템 상태 | API·DB·스키마·코퍼스·모델 가용성을 구분해 막힌 작업의 원인을 좁힙니다. |

코퍼스 준비, 데이터셋 편집, 실제 평가 실행, 로컬 모델 설정은 DEV가 필요합니다. 공개 방문자는 공개 대상 문서와 스냅샷을 읽고 허용량 안에서 설정된 OpenAI 답변 서비스를 사용할 수 있습니다. 요청의 선택 사항은 [설정](settings.md), 실행 기록의 의미는 [실행 상태](runtime.md)에서 설명합니다.

## 도움말과 문서 사용하기 {#help}

1. 현재 조작의 뜻이 궁금하면 **도움말**을 엽니다. 추천 주제는 현재 화면을 반영하며, 한국어·영어 검색을 현재 화면 또는 전체 섹션에 적용할 수 있습니다.
2. 주제를 열어 요약과 **사용 순서**를 읽습니다. **이 컨트롤로 이동**은 해당 조작에 포커스를 두거나 소속 화면으로 이동하며, 그 작업을 실행하지는 않습니다.
3. 전체 작업 순서와 선행 조건, 결과의 의미가 필요하면 **전체 가이드 읽기**를 선택합니다. 도움말의 **이전**은 이전 검색·필터·스크롤 위치를 복원합니다.

문서 메뉴는 17개 가이드의 읽기 순서를 유지합니다. 이전·다음 링크로 이어가고 언어를 바꿔도 같은 문서를 읽습니다. 코드 카드에서는 원래 명령을 복사하며, 넓은 표는 가로로 스크롤할 수 있습니다. 원문·질문·답변·모델명·로그는 작성된 언어를 유지합니다.

실패가 생기면 [문제 해결](troubleshooting.md)에서 기록된 증상에 맞는 확인 항목을 찾으세요. 구현 배경은 [아키텍처](architecture.md), 터미널이 필요한 작업은 [CLI 안내](cli.md)를 참고합니다.

### 이전·앞으로와 위치 복원

상단의 **이전**과 **앞으로**로 대화와 확인 화면 사이를 오갈 수 있습니다. 현재 위치를 누르면 **방문 기록**에서 항목을 고릅니다. 방향키·Home/End·Enter·Escape로 조작할 수 있으며 좁은 화면에서는 아래쪽 시트로 열립니다.

앱 이동과 브라우저 방문 기록은 같은 순서를 사용합니다. 돌아오면 유지 중인 조작 상태·대화 초안·포커스·스크롤을 복원합니다. 뒤로 간 뒤 새 위치로 이동하면 앞으로 경로가 바뀌며, 저장하지 않은 평가 질문에서 나갈 때는 여전히 확인을 요청합니다.

URL은 화면·탭·선택한 준비 단계나 평가 결과·로컬 대화를 식별하고, 새로고침하면 그 위치를 복원합니다. 이 브라우저에 없는 대화라면 가장 최근 저장 대화로 돌아갑니다. 메시지 본문과 작성 중인 질문은 URL에 포함하지 않습니다.

## 브라우저 저장소 {#browser-storage}

PROD의 대화·기본값·필터·프리셋·언어/테마·도움말 설정은 이 브라우저와 origin에 저장되며 동기화되지 않습니다. 사이트 데이터를 지우기 전에 **설정 → 데이터와 도움말 → 브라우저 저장소**에서 백업을 내보내세요. [저장소 안내](settings.md#browser-storage)는 저장 항목·가져오기·삭제 범위를 설명합니다. DEV는 자체 저장 동작을 유지합니다.

## 공용 OpenAI 사용 한도

공개 정책은 IP당 분당 2회·이동식 24시간 동안 5회, 전체 방문자가 공유하는 UTC 하루 $0.10, 모델 호출당 $0.005를 허용합니다. 텍스트 모델은 `gpt-5.6-luna`이고, 의미 검색은 `text-embedding-3-large`의 384차원 임베딩을 사용합니다. **사용 한도와 가용성**은 서버의 현재 가용성을 표시하며 계정 청구서나 보장된 답변 횟수를 뜻하지 않습니다.

답변 호출과 질문 임베딩은 OpenAI 호출 직전에 허용량을 예약합니다. 키워드 전용 검색과 저장 결과 열람에는 이 허용량을 사용하지 않습니다. IP 한도는 시간이 지나면 풀리고, 공용 일일 한도는 UTC 자정에 초기화됩니다. `data/runtime/public-ai-limits.sqlite3`의 예약 기록은 같은 영구 볼륨에서 앱을 재시작해도 유지됩니다. 한 호스트의 여러 프로세스를 조정하며 독립된 여러 호스트를 조정하지는 않습니다. [환경 준비](environment.md#production-deployment)에서 이 배포 경계를 설명합니다.
