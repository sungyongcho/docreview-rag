# 작업 흐름이 연결되는 구조

DocReview RAG v2는 SEC·DART 수집, 인용 가능한 문서 처리, 검색, 근거 검토, 검색 평가를 연결합니다. 이전 인터페이스는 v1.4 beta 기준이며 이 안내는 v2를 설명합니다. 제품 버전 표현을 바꿔도 저장된 데이터셋 ID·API 필드·저장소 URL은 바꾸지 않습니다.

아래 지도는 어떤 계층이 동작을 담당하는지 찾기 위한 것입니다. 구현을 읽기 전에 각 영역 옆의 작업 안내에서 사용 흐름부터 확인하세요.

## 공시에서 근거와 평가까지 {#flow}

1. **원문 수집:** SEC·DART 수집은 원문 파일과 manifest 메타데이터를 저장합니다. 회사 이름은 표시용이며 요청의 식별자는 고정된 회사 코드입니다.
2. **파싱과 청크 생성:** 적재 과정은 공시를 해석해 문서와 원문 연결 청크를 저장합니다. 청크는 인용을 확인할 문서 식별자·원문 해시·문자 범위를 유지합니다.
3. **검색 경로 준비:** 임베딩은 벡터 검색을, BM25 통계는 키워드 검색을 지원합니다. 둘은 병렬로 준비하는 경로입니다. 하이브리드 검색은 순위를 합치고 실제 프로필에 따라 후보를 재정렬할 수 있습니다.
4. **검색과 검토:** 질문 의도와 공시 범위를 정하고 근거를 검색한 뒤 관련성·답변·인용을 확인해 결과 또는 구조화된 실패를 반환합니다. 답변을 생성하지 않고 후보 근거만 반환하는 경로도 있습니다.
5. **독립적인 검색 평가:** 정답 데이터셋은 확인할 원문 범위를 제공합니다. 평가는 지정된 검색 설정에서 순위와 집계 지표를 기록합니다. 필요한 것은 원문과 인덱스이며 이전에 만든 답변이 아닙니다.
6. **결과와 검색 데이터 보존:** 현재 인덱스와 일치하는 빠른 평가를 스냅샷으로 저장할 수 있습니다. 방문자가 읽을 범위는 별도의 게시 동작으로 정합니다.

## 저장 위치·권한·공개 경계 {#boundaries}

원문 파일·manifest, PostgreSQL 문서·청크, 평가 산출물, 브라우저 대화는 서로 다른 저장소입니다. 다운로드는 DB 적재가 아니고, 브라우저 대화 저장은 검색 스냅샷 저장이 아닙니다. 브라우저 대화를 지워도 서버 문서는 삭제되지 않습니다.

| 자원 | 경계 |
|---|---|
| `/admin/*` | 문서 변경·평가·편집·로컬 연결에는 개발·운영 기능 권한을 적용합니다. |
| `/public/documents` | 준비된 공개 스냅샷 소속과 원문 식별자가 맞는 문서를 나열합니다. |
| `/public/documents/facets` | 같은 공개 목록에서 선택지와 개수를 제공합니다. 선택적 `registry=sec`, `registry=dart`로 범위를 좁힙니다. |
| `/public/documents/{doc_id}` | 문서 상세·청크 미리보기에도 같은 공개 경계를 적용합니다. |
| `/snapshots`, `/snapshots/compare` | 게시되고 준비된 스냅샷을 제공하며 기존 산출물을 비교합니다. |
| `/runs/{run_id}`, `/runs/{run_id}/traces` | 식별한 저장 실행과 트레이스를 읽습니다. 실행 목록 자원은 없습니다. |

공개 화면에는 미게시 문서의 총량·로컬 경로·인증 정보·관리자 동작을 노출하지 않습니다. 회사 이름도 같은 문서 공개 규칙을 따릅니다. 실행 데이터 초기화를 담당하는 로컬 운영자는 주 API 서비스와 별도이며 권한과 실행 상태를 따로 확인해야 합니다.

## 호환성과 실행 형태 {#compatibility}

회사 이름과 실행 측정 정보는 추가 메타데이터입니다. 이름이 없으면 고정 식별자를 표시하고, 과거 실행도 시간·라우팅 필드 없이 읽을 수 있습니다. `_v2_astra` suite ID는 그대로 유지합니다. 선택적 registry 필터가 없을 때는 기존의 통합 목록 기본 동작을 유지합니다.

단계 측정은 `X-DocReview-Telemetry: stages`로 요청할 때 추가됩니다. 헤더가 없는 클라이언트는 기본 스트림 순서를 유지합니다. 선택적 실행 메타데이터는 기존 JSON 저장 구조를 사용하며 UI 항목을 채우기 위해 필수 필드를 새로 만들지 않습니다.

개발 스택은 기본 포트 8000에서 앱과 실시간 편집 문서를 제공하고 소스 마운트·자동 갱신을 사용합니다. 정적 운영 이미지는 빌드된 앱과 두 언어의 문서를 포함합니다. `MODE`·백엔드 권한·공개/개발 웹 빌드 성격은 서로 관련되지만 다른 설정입니다. 지원하는 시작 절차는 [환경 준비](environment.md), [CLI 참고](cli.md)에 있습니다.

구체적인 실패가 생기면 다른 계층을 바꾸기 전에 [문제 해결](troubleshooting.md)에서 증상과 근거를 연결하세요.
