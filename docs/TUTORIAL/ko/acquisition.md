# SEC·DART 원문 수집

## 기본 수집 범위와 선택 항목

초기 선택은 디스크의 실제 원문에서 구성됩니다. 원문이 없으면 비어 있고, `schema_status recreate --sample`을 실행한 경우에만 **NVDA·AMD**, **2023·2024**가 선택됩니다. 자동 다운로드는 하지 않습니다. 회사 선택지는 현재 manifest에서 읽으며 인제스트 전에도 사용할 수 있습니다. 기본 manifest에서는 SEC의 NVDA·AMD·INTC·MU와 DART의 삼성전자(005930)·SK하이닉스(000660)·NAVER(035420)를 선택할 수 있습니다. 하나의 통합 목록에서 회사를 선택합니다. SEC와 DART는 색상과 문자 배지로 구분하며 별도의 소스 탭은 없습니다. 두 소스를 함께 선택하면 공급자별 작업으로 나눠 등록하고 공통 manifest에 각각의 처리 선택을 유지합니다.

기본 테스트 연도 추천은 **2020–2024**입니다. 추천 연도를 자동으로 선택하지 않으며, 선택 가능하다는 사실이 공급자에게 해당 공시가 있다는 뜻은 아닙니다. 원문 준비 수는 실제로 존재하는 주 문서 기준이며 압축 파일이나 겹치는 처리 선택을 중복 집계하지 않습니다.

스키마 불일치로 인덱싱이 막혀 있어도 원문 저장과 작업 기록 저장이 가능하면 수집은 진행할 수 있습니다. 스키마 문제에 HOST_GID를 바꾸지 말고 별도의 진단을 확인하세요. 수집을 마치면 파싱·청킹은 원문 단계의 회사·회계연도 선택을 자동으로 이어받습니다.

회사·연도 추천은 입력창 바로 아래에서 주변 안내와 빠른 추가 버튼 위에 겹쳐 열립니다. 같은 목록에서 SEC와 DART 회사를 함께 선택하며 출처 배지로 구분합니다.

수집은 보고서 원문을 내려받고 공통 `manifest.json`에 문서 식별 정보를 기록하는 단계입니다. 파싱과 DB 저장은
그다음에 수행합니다. 먼저 [문서 목록](documents.md#step-2)을 확인하고 이미 준비된 원문은 재사용하세요.

## 3. 출처·기업·회계연도 선택 {#step-3}

- **목표:** 준비할 보고서의 범위를 정합니다.
- **선행 조건:** [환경 확인](environment.md#step-1)을 마쳤고 부족한 보고서를 파악했습니다.
- **화면 경로:** 데이터 준비 → 파이프라인 → 원문 수집 → 변경….
- **입력:** SEC EDGAR에서 `NVDA`, `2024`를 선택합니다. 한국 보고서는 DART에서 `005930`, `2024`를
  선택할 수 있습니다. 연도는 보고서의 회계연도이며 공시가 게시된 연도와 다를 수 있습니다.
- **주 동작:** 기업과 연도를 칩으로 선택합니다. 이 동작은 입력만 준비하고 다운로드하지 않습니다.
- **화면 변화:** 유효한 코드와 연도가 제거 가능한 칩으로 표시되고 터미널 참고 명령에도 같은 값이 반영됩니다.
- **완료 기준:** 출처·기업·연도가 의도한 보고서와 일치하고 잘못된 입력 초안이 남아 있지 않습니다.
- **실패와 복구:** 오류가 표시된 입력을 수정하고 Enter를 누르세요. 인증이나 보고서 조회 오류는
  [수집 문제 해결](troubleshooting.md)에서 확인합니다.
- **다음:** [누락 원문 다운로드](#step-4). 원문이 있으면 [파싱](indexing.md#step-5)으로 이동합니다.

기존 기업은 코드나 회사명으로 검색할 수 있습니다. 이름은 실제 원문 메타데이터에서 가져오며,
이름이 없거나 충돌하면 코드만 표시합니다. 회사명을 선택해도 요청에는 같은 식별 코드가 전달됩니다.
여러 코드를 붙여 넣을 수 있고 필요 없는 칩은 개별적으로 제거합니다.

회계연도는 네 자리 숫자입니다. `2023-2025` 같은 오름차순 범위는 연도별 칩으로 펼쳐집니다.
최대 50개 연도를 허용하고 중복을 제거합니다. 잘못된 초안은 화면에 남고 수집 실행을 막습니다.
필드에서 포커스를 옮겼더라도 오류를 수정한 뒤 실행하세요.

## 4. 누락 원문 다운로드 {#step-4}

- **목표:** 파싱에 필요한 원문 파일을 준비합니다.
- **선행 조건:** 3단계의 입력이 유효하고 [출처별 인증 설정](#sources)이 준비돼 있습니다.
- **화면 경로:** 데이터 준비 → 파이프라인 → 원문 수집의 선택 단계 실행 영역.
- **입력:** 동작 위에 표시된 출처·코드·연도와 처리할 manifest 범위를 다시 확인합니다.
- **주 동작:** **누락된 원문 다운로드**.
- **화면 변화:** 대기 또는 실행 중인 작업이 생깁니다. 데이터 준비 → 작업에서 진행 상황과 실제 결과를 읽습니다.
  작업이 끝나면 준비 상태가 자동으로 갱신되므로 수동 새로고침은 필요하지 않습니다.
- **완료 기준:** 작업이 성공했고 반환된 처리 선택의 원문이 준비됐습니다. 다른 항목의 원문이
  부족하면 전체 단계는 여전히 미완료로 표시될 수 있습니다.
- **실패와 복구:** 작업 오류와 대상 문서를 확인한 뒤 재시도하세요. 실패·취소·재시작으로 인한 중단은
  서로 다른 상태이며 지원되는 상태에서만 재시도가 표시됩니다. [작업 진단](troubleshooting.md)을 참고하세요.
- **다음:** [파싱과 청크 생성](indexing.md#step-5).

SEC와 DART는 공통 `manifest.json`을 사용합니다. 선택한 출처·기업·회계연도가 수집 범위를
정합니다. 작업 결과의 `selection_id`는 실제로 수집한 원문을 명시하며, 같은 선택 ID로 DB 적재와
임베딩 준비를 진행합니다. 다른 카탈로그 항목은 그대로 보존되며 이 선택에 자동으로 포함되지
않습니다. [단일 공시 CLI 절차](cli.md#nvidia-한-건만-준비하기)도 같은 계약을 사용합니다.

## 출처별 준비 사항 {#sources}

| 출처 | 식별자 | 필요한 설정 | 공통 manifest |
|---|---|---|---|
| SEC EDGAR | `NVDA` 같은 티커 | 실명과 연락 가능한 이메일을 넣은 `SEC_USER_AGENT` | `manifest.json` |
| DART | `005930` 같은 6자리 종목 코드 | 유효한 `DART_API_KEY` | `manifest.json` |

인증 정보는 로컬 설정에 보관하세요. 스크린샷·요청 예제·Git에는 넣지 않습니다. 설정 적용이 필요하면
[환경 준비](environment.md)를 따릅니다. 이 문서를 읽는 동작은 수집이나 모델 호출을 실행하지 않습니다.

다운로드 원문은 DB 문서·청크·임베딩·공개 스냅샷과 별개입니다. 각 경계는
[구현 구조](architecture.md)에서 확인할 수 있습니다.

## 다운로드 상태와 현재 선택

**다운로드된 원문**은 등록기관 → 회사 → 회계연도별 원문 준비 수를 **변경…** 초안과 별도로 보여 줍니다. 초안에서는 선택한 원문 중 준비된 수, 다운로드가 필요한 회사/연도, 다운로드되어 있지만 선택하지 않은 수를 확인합니다. 선택 변경은 파일을 삭제하지 않습니다. 현재 선택이 비어 있지 않고 필요한 원문이 모두 있을 때만 완료이며, 빈 초안이나 누락 원문은 작업 필요 상태입니다.

처음에는 실제 디스크 원문을 기준으로 초안을 구성합니다. 다운로드가 끝나면 목록을 갱신하며, 수정하지 않은 초안은 실제 원문에 맞춰 자동으로 동기화합니다. 직접 수정한 초안은 보존하며, 원문 상태가 바뀐 경우 **다운로드된 원문과 초안 동기화**로 회사·연도 범위를 명시적으로 맞출 수 있습니다. 파싱 및 청크 생성의 **원문 단계에서 선택 변경**으로 돌아오세요. `uv run python -m scripts.schema_status recreate`는 빈 상태로, `--sample`은 NVDA/AMD FY2023–2024 초안으로 시작하며 다운로드는 직접 실행합니다. `--keep-sources`는 원문을 보존합니다. 더 넓은 초기화인 `rag-fresh-start`와의 차이는 [CLI 안내](cli.md)를 확인하세요.
